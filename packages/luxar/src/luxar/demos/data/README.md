# Demo Data Files

This directory contains the small set of demo assets that still live in the
repository. The manifest is the source of truth for every dataset:
[`../data_manifest.json`](../data_manifest.json) records its acquisition bucket,
license, files, sizes, and checksums. A file entry can carry two checksum
contracts: `sha256` for the copy this repository ships, and an optional
`hosted_sha256` (with `hosted_bytes`) for the copy the Zenodo record serves when
a refit made the two differ. Only `census_umap_1m.npz` and the two
`3d_umap_coords_*.parquet` files are still shipped here; every other `zenodo`
entry carries `sha256` alone, and for those it describes what the record is
meant to serve — that single pin is what the download leg will verify against
once the records are published, with the three exceptions listed below. It is
generated by
`scripts/gen_data_manifest.py` (`make gen-data-manifest`, checked in CI by
`hatch run check-data-manifest`) and read by
`luxar.utils.data_fetch.ensure_dataset`.

The manifest lives above this directory because `demos/data/` is excluded from
wheel and sdist builds.

## How Data Is Obtained

| Bucket | Meaning |
|--------|---------|
| `zenodo` | Redistributable derived products fetched on demand into `~/.cache/luxar/`. |
| `local-compute` | Non-redistributable products rebuilt from their original source. |
| `regenerate` | Small products rebuilt locally without hosting. |

The large precomputed GSplat and scene archives have moved out of Git LFS and
are pinned in the manifest. Their three Zenodo records are still unpublished
drafts on this branch, so the manifest intentionally builds no download URL yet.
Publish those records and enable their manifest URLs before merging the payload
removal.

Three of the drafts' files need work before that publication, because `dev`
moved after they were uploaded. `blastocyst_ch0.gsplats.zarr.zip` and
`blastocyst_ch1.gsplats.zarr.zip` are on the `cc-by` record under their former
`organoids_ch*` names — the bytes are the ones pinned here, so those two only
need renaming on the record, plus a regenerated description (
`scripts/gen_zenodo_records.py` names every file in the contents table).
`zebrafish_4d.gsplats.zarr.zip` is on the
`cc-by-sa` record as the pre-component-filter build, and the pin here describes
the current one, so it needs replacing and its pin re-deriving from the
deposition. `scripts/zenodo_migration_audit.py --live` reports both.

Five datasets are `local-compute`. For four of them — `gsplats_tribolium`,
`gsplats_acto3d_heart`, `gsplats_tng_cosmic_web` and `milky_way_gaia_3m` — the
licenses do not permit redistributing even the derived product, so do not
migrate those demos to the manifest fetch path. `gsplats_flylight_mcfo` is the
exception: it is CC BY 4.0 and redistributable, and is `local-compute` only
because its record does not exist yet — promote it to `zenodo` / `cc-by` once it
does. **Their in-repo copies have been removed**: those demos now fetch the raw
source and rebuild locally. Gaia's opt-in first-run path queries the archive
with `--build-catalog` and caches the result in `~/.cache/luxar/`.

A `zenodo` dataset's files are fetched to `~/.cache/luxar/<dataset>/<file>`, and
that path belongs to the fetch: it checks the manifest checksums there and
quarantines (renames `.corrupt`) anything that fails. So a demo that has to
build its own stand-in — a GPU refit, when the record is not published yet and
the Git LFS object was never pulled — writes it to the sibling namespace
`~/.cache/luxar/<dataset>/local/<file>` via
`luxar.utils.data_fetch.local_fit_path`, which the fetch never inspects. Under
the hosted name it would be quarantined on the next launch and refitted every
single time (#1618). `luxar demo cache clear` counts anything under `local/` as
a *computed* artifact, so `--no-computed` spares it — but only what is under
`local/`: a computed artifact a demo writes directly into its cache dir is
still classified as a download (see `demos/README.md`).

Licenses split three ways: mostly CC0 / CC-BY / public domain; **CC BY-SA** for
`gsplats_zebrafish` and `gsplats_opencell_map4` (the derived product must be
relicensed CC BY-SA 4.0); and **CC BY-NC** for `milky_way_gaia_3m` (non-commercial,
with a mandatory ESA/Gaia/DPAC acknowledgement). See the `license` field per
dataset in the manifest.

## Files Remaining Here

| Path | Purpose |
|------|---------|
| `3d_umap_coords_human.parquet` | Human cell UMAP coordinates. |
| `3d_umap_coords_mouse.parquet` | Mouse cell UMAP coordinates. |
| `census_umap_1m.npz` | Direct package-data fast path for the CELLxGENE Census UMAP demo. |
| `dipc_genome/dipc_gm12878.npz` | Dip-C GM12878 bead coordinates for the 3D genome demo. |
| `gsplats_cmu1_pathology/.gitkeep` | Placeholder for the manifest-managed pathology dataset. |

The parquet files and both `.npz` files are Git LFS objects. If one appears
as a small pointer file, materialize only that retained asset with Git LFS. The
removed GSplat archives cannot be restored with `git lfs pull`; once published,
their demos resolve them through the manifest instead.

## File Formats

- `.npz`: NumPy arrays used directly by a demo.
- `.parquet`: tabular UMAP coordinates.
- `.gsplats.zarr.zip`: manifest-hosted Gaussian splat datasets.
- bundle `.zip`: manifest-hosted timelapse bundles containing per-frame stores.

See individual demo scripts and the manifest for source and license details.
