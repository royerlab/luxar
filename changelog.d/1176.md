#### GSplat floor specifications now resolve consistently across fitting paths

Percentile floors now ignore exact-zero padding like the default histogram-mode
estimator, and the public floor estimator materializes array-like inputs before
filtering them. For per-array normalization, the non-tiled erase-all guard now
uses the data maximum, matching tiled, progressive, and calibration fits; when
a configured `norm_percentile` high endpoint lies below a valid floor,
normalization expands to that maximum rather than silently refusing the floor.
A re-plan of an existing padded `batch-fit` output can therefore resolve a
different `floor_level` than the one recorded for its already-fitted tiles.
A supplied whole-volume `norm_range` remains authoritative across every tile.
CLI help and the pipeline guide now spell out the intentional `--floor 0` alias
for `none`, the percentile low-end clamp, zero-padding treatment, and
negative-level behavior.
