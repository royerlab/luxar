#### `capture-hires` readiness gate now recognises all four geometry types

The high-resolution capture tool warned "no elements loaded" for a mesh-only scene that
had in fact rendered correctly — and, it turns out, for every other scene too. Its
readiness check read the element totals from a `state.performance` sub-object, but
`window.__luxarDebug.getState()` returns its `DebugState` FLAT and has never had a
`performance` key. So the totals were always `undefined`, `undefined > 0` made the
verdict false for points, lines, gsplats and mesh alike, and `JSON.stringify` silently
dropping the `undefined` keys hid the shape mismatch from the printed diagnostics.

The verdict now lives outside the `page.evaluate` closure as a pure, unit-tested helper
(`summarizeCaptureReadiness` in `core/app/debug/capture-readiness.ts`); the browser side
does nothing but hand the snapshot back verbatim. It reads the flat fields and reports
all four geometry types — `totalPoints`, `totalGSplats`, `totalLines`, `totalTriangles`
plus the per-node `pointCloudCount` / `gsplatCount` / `lineCount` / `meshNodeCount` — so
a mesh-only or lines-only scene reads as loaded instead of as empty, and a genuine
failure names its reason rather than leaking `NaN`.
