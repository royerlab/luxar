#### A fit in physical coordinates still gets a PSNR

`output_space="real"` is the default, so a fit handed a `voxel_size` returned
splats in physical coordinates — and the post-fit quality metrics were skipped
outright, because those coordinates no longer matched `config.V`'s grid. Ten
demos pass a `voxel_size`, so ten cached archives were being written with no
`psnr_db` at all and, since the foreground metric landed, no
`foreground_psnr_db` either.

The conversion is a pure per-axis rescale of centers and Cholesky rows with
amplitudes untouched, so the pre-conversion arrays describe the same mixture on
the fitted grid. They are kept and scored; the caller still receives physical
coordinates. It costs one round-trip render — the same one the voxel-space path
has always paid, but genuinely new work on a real-space fit, which did none
before, and once per tile on a real-space tiled fit.

A test asserted the old behaviour — that the metrics were skipped — which had
quietly turned the defect into a contract. It now asserts the metrics are
present, and that the returned centers are still physical so the scoring copy
cannot leak back. A new equivalence test scores the same fit through both output
spaces and requires the same PSNR, under a deliberately anisotropic voxel size:
an isotropic one would hide a per-axis bug in the row-by-row Cholesky scaling.

`fit_tiled` remains without a merged-volume PSNR of its own — the tiles overlap
and are apodized, so per-tile errors do not compose into the merged one.
