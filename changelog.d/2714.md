#### A touch panel for the kiosk, with no authoring required

`control.html` is a second page in the viewer bundle, meant for a tablet beside
a big display: a full-screen grid of chapter tiles, and tapping one jumps the
display to that stop of the tour. `luxar serve --control` prints both URLs.

It needs nothing added to a scene. A labelled dimension —
`Dimension(categories=[...])` — already carries the stop names, so the page asks
the viewer what dimensions it has and reads the labels that are there. Tours
built long before this page existed get a working menu against their existing
stores. Where a scene has no chapter dimension, or the page was opened with no
hub to talk to, it says so in words instead of drawing an empty grid.

The page is deliberately light: no renderer, no codecs, its own small
stylesheet. The build now checks that per page rather than globally — the viewer
may ship `three` as long as the WebGPU path stays lazy, while the panel may
reach neither, which is not something a source-level lint can see.

Two things an author can rely on. The tile classes, `data-*` state hooks and
`--luxar-control-*` custom properties are a styling contract, pinned by a test
from both the DOM and the stylesheet side, so a rename cannot quietly break a
scene's own CSS. And `?panel=<module>` loads an alternative panel, handed an
already-connected socket, for the exhibit that outgrows CSS — same-origin only,
since that module is executed.
