#### Background-floor provenance is recorded on every gsplat writer path, and `fit --cal` consumes it

The background level a fit subtracts is the only way to interpret the amplitudes
it stores — they are background-relative, never restored — yet almost nothing
persisted it under a name a reader could find. The flat non-tiled fit recorded
it as `floor`; a flat tiled merge recorded the same fact under a different name
(`applied_floor`); a `kind=partition` merge stamped that name onto a node `meta`
key the tree writer discarded; a `--tiling content` fit, a `--progressive` fit
and a `batch-fit merge` recorded nothing at all; and `GSplatData.concatenate`
built a fresh stats dict that dropped every tile's block on the way to the
merge. The format spec claimed otherwise.

There is now one key name (`floor`, alongside `image_min` / `image_max` /
`intensity_range`) in one location (the store's `pipeline/` group), written by
every fitting path: a tree carries the block on its root node's `meta` and
`write_gsplats_tree` promotes it, so a partition and a flat leaf answer the same
question the same way; the parallel `fit -j` merge reloads its worker tiles WITH
their stats and recovers the level from them; and `batch-fit merge` takes the
one level its plan pinned off the manifest. The values are in the input volume's
own units — a tiled or progressive path removes the pedestal outside the fitter
and then fits with `floor="none"`, so it shifts its inner bounds back by the
applied level rather than recording a post-subtraction minimum that means
something different from every other path's. Merging is unanimous-or-silent:
`concatenate` carries a key only when every input that records it agrees,
because two independently fitted volumes have two different pedestals and
promoting the first input's would mislabel the rest. A path that cannot name one
honest level writes no key at all, because `floor: null` asserts that no
pedestal was removed. `gsplat info` now lists the block — on its node-tree
report as well as its flat one — instead of burying it in the generic metadata
dump.

`gsplat cal` recorded the floor it subtracted in `fit_config.floor_subtracted`
and nothing read it, so a `cal --floor p20` followed by
`fit --tiling content --cal cal.json` measured the density's `feature_threshold`
at `p20` but scanned and fitted at `auto` — a silent scale mismatch. `fit` now
adopts the calibration's level when the user said nothing about `--floor`,
announcing where the floor came from. Only under `--tiling content`, the one
mode that honours `--cal` at all. An explicit `--floor` (including
`--floor auto`) still wins, as does a `floor:` in a YAML `--config`. A recorded
`null` is NOT adopted: `cal` writes it both when the user asked for `none` and
when its own too-high guard refused the level, and the file cannot tell the two
apart. The adopted level is absolute, so reusing one `cal.json` across a
timelapse applies the calibrated timepoint's pedestal to every other one — said
so in the `--cal` help.
