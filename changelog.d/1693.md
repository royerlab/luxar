#### The CI diff classifier now names gate inputs that carry no Python extension

`.github/workflows/ci.yml` sorts a PR diff into language domains and runs each
suite only when its domain is set, but `scripts/complexity_baseline.json` matched
none of the patterns. Since the C901 ratchet is enforced by a pytest test inside
`hatch run test-cov`, a baseline-only diff reported `python-tests (3.12)` green in
about seven seconds without ever running the check whose entire job is to assert
that the tree still matches that baseline — observed on #1678. That check is what
catches a baseline that has come loose from the code: keys dropped while still over
the limit come back as newly over-complex, values below what the tree measures come
back as worsened, and an emptied file trips a fail-closed assertion. (It does not
police a deliberately raised entry — the ratchet reads that as debt paid down
elsewhere — and #1678's own baseline was in fact a legitimate tightening. The hole
was real even though the harm did not land there.)

The classifier now also owns the other non-Python inputs read by pytest:
`scripts/gallery/manifest.json`, `docs/guides/user/CLI_REFERENCE.md`, the root
`README.md`, and `packages/luxar/src/luxar/demos/README.md`. Their guards
cross-validate the gallery manifest, live CLI, demo documentation, and exported
helper inventory; a JSON- or Markdown-only diff previously skipped those tests.
The guard table also covers the viewer fixture-generation entry points already
classified for `test_fixture_environment.py`.

A new guard, `packages/luxar/src/luxar/tests/test_ci_diff_classifier.py`, keeps the
principle the `changes` job already states in its own comment: every input of a
gated check must be classified into the domain that runs it. It extracts each
domain pattern from the workflow text and evaluates it with a real `grep -E` — the
matcher CI actually uses, rather than Python's subtly different `re` — over a table
of gate inputs that carry no Python extension. Negative controls run
against all four language domains and against the documentation gate, so a pattern
that had degenerated into a catch-all fails instead of passing everything, and the
rule that puts the workflow file itself in every domain — the only thing that
classifies it at all — is now pinned too.
