#### The node-attrs gate now runs once, at the adder entry, ahead of every split path

`add_points` / `add_lines` forward the caller's `**attrs` unchanged into three
structurally different split paths — `substitutive_lod=` (synthesised gsplat
coarse levels under a `kind=lod` group), `partition=` (a `kind=partition`
group of BSP parts), and `additive_lod=` (a progressive `additive_<i>`
ladder) — before ever reaching the flat writer's own node-attrs validator
(`validate_render_attrs`). All three paths could strand bad output or report
the wrong verdict. A bad node attr on `substitutive_lod=` — e.g.
`amplitude_range=`, which `GSPLATS_RESERVED_ATTRS` reserves but
`POINTS_RESERVED_ATTRS`/`LINES_RESERVED_ATTRS` do not — was refused only from
inside the synthesised gsplat `child_0`; by then the `kind=lod` wrapper group
itself was already on disk, childless (`child_0` is the FIRST coarse level,
so nothing else had been written yet). The same was true of `partition=`:
`add_points("p", pos, partition={"max_elements": 100}, blending="max")`
raised the right message but left a childless `kind=partition` node for
`"p"` on disk, and that node survived `finalize()`. `additive_lod=` was
worse: the multi-LOD writer calls the validator with no reserved-attrs set at
all, so a genuinely points/lines-RESERVED key like `ordering=` or
`max_radius=`/`max_width=` was reported as an *unknown attribute* instead of
the correct #1221 *reserved* verdict (the `LuxarZarrCompiler(ordering_method=...)`
hint fires only for `ordering=`) — nothing was written either way; and
a caller-supplied `position_bounds=` alongside `additive_lod=` didn't raise
at all (it isn't reserved from the multi-LOD writer's point of view) — real
ladder data was written and the writer's own stamp clobbered, and
`finalize()` then failed later with an unrelated `ValueError: Could not
finalize Zarr store: list indices must be integers or slices, not str`.

Both adders now run the flat writer's own gate once, on the un-split caller
attrs, at the adder entry — above every structural branch, so nothing is
written before it runs. The split paths now refuse byte-identically to the
flat path (same message, same exception type, same reserved-vs-unknown
verdict) with nothing written; the flat path itself simply validates twice
(idempotent — the function only inspects `attrs`), which also means a
multi-fault flat call now reports the attrs fault where it used to report an
`extend_to_all` fault (attrs now validate first, matching the writer's own
step 0a). This mirrors the #1446 dimension-count gate, which already sits at
this same adder-entry point; the nearest precedent for the validator itself
is mesh's own `_maybe_add_mesh_substitutive_lod` (`mesh.py:401-403`), the
substitutive branch's dispatcher, which already calls it before ever handing
off to the wrapper. It does **not** mirror the
#1437 channel gate, which deliberately stays at the top of each wrapper
(per-element channels are only sliceable once a split has been decided) — the
new attrs gate, sitting above the wrapper, now outranks it, matching the flat
writer's own order (`validate_render_attrs` before the channel sweep). A
compositing attr (`opacity=`, `blending_mode=`) was already refused before
this fix, with nothing written, via a separate wrapper-level check; the fix
also makes those compositing-value refusals byte-identical to the flat
message, which they were not before. Mesh and GSplats did not gain this
gate here — their own `partition=` paths still stranded a childless
`kind=partition` node; #1534 closes that, see the entry below.
