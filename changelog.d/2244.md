#### Preserve encoded image overlay formats (#2244)

Image overlays created from paths or pre-encoded bytes now use a filename
extension that agrees with the payload. Keeping the stored member name and
`image_file` metadata aligned gives viewers the correct URL and ensures renamed
payloads invalidate content hashes. Pre-encoded payloads outside PNG, JPEG, and
WebP are now rejected, as are recognized path extensions that contradict the
payload format.
