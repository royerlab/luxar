#### The viewer now says which build it is

Every viewer bundle carries its version, commit and build time. `window.__luxarBuild`
is attached before init and without needing `?debug`, a startup log line reports the
same, and `index.html` gets a `<meta name="luxar-build">` tag that survives a bundle
which fails to boot — greppable in an unzipped wheel or an emailed `luxar export`
folder. Embedders can read it directly through the new `buildInfo()` export.

The stamp is applied once at Vite build time and so reaches the dev server, the PyPI
wheel, `luxar export` output, the npm library bundle and the hosted site together. It
never fails a build: a checkout with no git history is stamped `commit: "unknown"`
rather than erroring, and a dirty tree is marked as such so a dev build cannot point
a reader at source that is not what ran.

This also replaces `__luxarDebug.version`, which was the hardcoded string `'1.0.0'`
in two places — a wrong version being a worse diagnostic than no version, since the
claim looks authoritative.

A new `check-build-identity` gate reads the emitted files and fails if a bundle ships
unstamped or with a version that disagrees with `package.json`. It runs inside the
existing `wheel-viewer` and `release-readiness` CI jobs.
