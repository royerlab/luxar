#### The Zenodo record descriptions are generated from the data

The three demo records describe several dozen files between them, each with a
splat count, a compression figure, a reconstruction quality and a licence. Typed
by hand those drift from the data within one refit, and a record is the one place
where a stale number is published rather than merely wrong.

`scripts/gen_zenodo_records.py` derives the text instead: disposition and
licensing from the manifest, per-file characteristics from each archive's own
`fitting/` stamps, with anything unstamped printed as absent rather than guessed.
`--check` turns the same read into a work list of rows that would publish
incomplete. The script never contacts Zenodo — it writes markdown for a human to
paste, and publication remains a manual act.

Two claims it would otherwise have made falsely are now impossible. An `.npz` is
also a zip and a point-cloud `.luxar.zarr` is also a zarr store, so both parsed
as splat stores and came back defaulted — one dataset was described as having
"single level" detail when it holds no splats at all. The reader identifies the
format before describing it, and datasets that are not fits get a plain file list
rather than a table of dashes implying unmeasured figures.
