#### Clicking a picked element can now open a link or copy a string (#1917)

A labelled element could be **named** on hover and nothing else. Left- and
right-click on the canvas did nothing at all: outside the camera controls
nothing in the viewer listened for `click`, `contextmenu`, `mousedown` or
`pointerdown`, and both controls implementations already suppress the native
context menu, so a right-click was swallowed and replaced by nothing.

Three new per-node attrs make an element actionable. They are plain `.zattrs`
values riding the existing `**attrs` pass-through, so no adder signature
changed:

```python
scene.add_gsplats(
    "organs", centers=..., labels=organ_names,
    link="https://en.wikipedia.org/wiki/Special:Search?search={hover_label}",
    copy="{hover_label}",     # optional — defaults to the bare label
    link_target="_blank",     # optional — the default
)
```

Left-click (no drag) opens the resolved URL; right-click (no drag) opens the
shared context menu with `Copy "<text>"`, `Open link in new tab` and `Copy link
address`, omitting whatever the element does not offer and not opening at all
when it offers nothing. The hover placeholder vocabulary is reused verbatim, so
there is one substitution to learn; it now lives in one place
(`utils/hover-template.ts`) shared by the tooltip, the link and the copy string,
with the escaping — and only the escaping — differing per consumer. The
totalsegmentator CT demo adopts it: every organ links to a lookup of its own
name.

Templates are authored per **node** rather than per hover overlay because a
scene has effectively one overlay but many layers, and the target is a property
of the data ("these are UniProt accessions"), not of the tooltip's presentation.

A click acts on the settled hover pick rather than taking a fresh one. That is
partly honesty — it is the element whose name the user just read — and partly
necessity: there is no synchronous pick, and awaiting a GPU readback risks
spending the browser's transient user activation, turning "open the link" into
"popup blocked". Staleness is covered by counters `PickingSystem` already
maintains: `pickGeneration` (camera move, resize, ortho swap, FOV edit, mouse
move, leave, dispose) and the new public `visibleSignature`, which catches a
layer-visibility toggle — the one invalidator that deliberately does not dirty
the pick buffer. `suppress()` pointedly does *not* advance the generation,
because pointerdown → `start` → suppress is the first half of an ordinary
click; a test pins that, since the failure mode would be every click silently
refusing itself.

Click is told from camera gesture by movement, never by button: which button
orbits and which pans is platform-dependent (`naturalDrag` defaults to macOS,
and ortho maps RIGHT to nothing), so any button-based rule would be wrong on
half the installs. A press that moves ≤4 px is a click. The menu opens on
`pointerup`, not on the `contextmenu` event, because on macOS the latter fires
at press time and a right-drag to rotate would pop a menu as the drag began;
macOS Ctrl+primary-click is treated as secondary, as in every native app.

Both halves of a link are untrusted — the template is author-supplied and the
substituted values are per-element data — so the guard is layered: values are
percent-encoded (a label may contribute content to a URL but never structure),
the result is parsed with no base so a relative template is refused rather than
resolving against the viewer's own origin, the scheme must be `http`/`https`
(an allowlist, deliberately stricter than the denylist used for *rendered*
markup — this URL gets navigated to), the length is capped, and links open with
`noopener,noreferrer` to a target restricted to the two keywords that imply it.
The Python writer runs the equivalent check, so a bad `link=` fails the write
instead of becoming a click that silently does nothing. A referenced
placeholder that resolves empty suppresses the action rather than leaving a
hole — `https://uniprot.org/{hover_label}` with no label is a valid URL to the
wrong place, and that is the *normal* case at coarse levels of a substitutive
LOD ladder, whose synthesised gsplat levels inherit the node attrs but carry no
labels.

Also included: a `pointer` cursor over a linked element; Shift+F10 and the
ContextMenu key as the keyboard path the UI design guide requires of every
context menu; `element-click` / `element-contextmenu` embedder events carrying
the element, the gesture and the resolved link; and a kill switch —
`allowLinks: false` or `?no-links` — that suppresses navigation, the link menu
items and the cursor while leaving `Copy` working, for embedders showing scenes
they did not author.

One provisioning subtlety worth knowing: a node declaring `link` or `copy` now
counts as a picking consumer in its own right, in both the early-return gate
and the live `shouldPick` predicate. A layer with a link but no labels (a link
built from `{hover_index}` is perfectly usable) auto-injects no hover overlay
either, so without that it would never pick and the link would never fire.

Touch is out of scope: there is no hover, so the cached-pick path has nothing
to act on and a tap does nothing. A follow-up would need tap → async pick →
in-tab navigation (the awaited readback may have spent the user activation) and
long-press → menu.
