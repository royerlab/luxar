#### Viewer disk cache: no stale bytes across tabs; one-time cache reset

With two tabs open on one dataset across a republish, the tab still on the old
version could write its chunks into the shared on-disk (OPFS) cache after the
newer tab had moved the cache to the new version. The next session then served
those old bytes. Each cached chunk file now carries a tag of its dataset's
content hash, and a viewer reads and keeps only files with its own tag. Because
the file naming changed, every existing disk cache starts fresh once after
upgrading. The background tidy-up of unindexed cache files also no longer
re-adds evicted entries or overruns the size cap.
