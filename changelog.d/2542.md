#### The CUDA and Metal backends could not be built at all — fixed

Both native build paths pinned `-std=c++17`, in the position where PyTorch appends
its own `-std=c++20` first and the last flag wins. Current PyTorch refuses to be
compiled below C++20 outright (`#error C++20 or later compatible compiler is
required`), so this did not merely relax the standard — it stopped the extensions
compiling. The Metal package builds itself the first time you use it, so the failure
landed on users of `luxar[gsplats]` on Apple silicon rather than in any build.

Both are now on C++20, verified by rebuilding the Metal extension end to end and by
compiling the CUDA bindings against PyTorch's headers at each standard.

`make check-native` is the check that would have caught it: it syntax-checks every
shipped CUDA and Metal source — about 3,900 lines that until now nothing compiled,
linted or checked — without needing a GPU or a CUDA toolkit, and reports each
toolchain it cannot find rather than passing silently over it. It runs in CI.

The numeric parity tests against the PyTorch reference do already exist for both
backends, and are substantial; they are skipped without a GPU, so they never run
automatically. Both backends' READMEs now say plainly what is and is not verified,
rather than leaving it to be assumed.
