#### Progressive batch fitting no longer claims to produce a LOD ladder

The `--progressive` help for `luxar gsplat batch-fit run` and `submit` now
describes the option as an optimization schedule that returns one flat splat
set per tile. It also points partition outputs to `luxar gsplat additive`,
documents that content tiling rejects the option, and keeps `--merge-recipe
stream` as the direct way to build ladders during batch merging. The matching
Python API docstrings now use the same contract.
