#### Stepping through a per-timepoint partition no longer leaks GPU memory

On a `kind=partition` time-lapse with one part per timepoint, every part the
user stepped away from stayed resident: its GPU buffer remained "active", which
the byte-budget evictor never touches, and its decoded ladder kept counting
against the refinement working-set cap. Resident VRAM grew by one part per step
(4.75 GB after 40 steps on a real scene, far past the logged budget), and the cap
then refused LOD rungs for the parts actually on screen. A loaded part that
leaves the committed slice now returns its buffers to the evictable pool and
drops its decoded ladder; stepping back re-sweeps it (restoring from the slice
cache or re-streaming), and each leaf that gave back a pooled buffer fully
recommits before the part is shown again; a mesh leaf, which keeps an empty
placeholder, never holds its siblings back. A frustum cull does not release anything, so panning past a part
never triggers a reload.
