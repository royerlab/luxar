#### `poisson-disk` LOD ordering is no longer quadratic

Authoring a Points or Lines ladder with `additive_lod=dict(method="poisson-disk", …)`
was O(N²), not the O(N) its docstring claimed. The cell grid used to accelerate the
rejection test held *every input point* rather than only the accepted samples, and at
the coarsest radius that grid is just a few cells across — so the neighbourhood scan
covered the whole dataset and every candidate was tested against every point. On a
million points it extrapolated to about four and a half hours.

The grid now holds accepted samples only, which is what Bridson's algorithm calls for.
Cost is a flat 24 µs per point from 10K to 1M points — 1M now takes 24 seconds.

The output is unchanged, and deliberately so: the neighbourhood search was already
correct, only the set scanned inside it was wrong. The permutation and per-level counts
are bit-identical to before across 320 configurations spanning eight point
distributions, and a new `test_cost_grows_linearly_with_n` fails if the quadratic ever
returns.
