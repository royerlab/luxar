#### Remote control: a viewer can now be driven from outside the page

A Luxar viewer on a big display can be driven by something else — a kiosk touch
panel, a script, an agent. `luxar serve --control` mounts a WebSocket relay at
`/control` on the viewer app, a viewer loaded with `?control` attaches to it,
and `luxar.control.Viewer` is the other end:

```python
from luxar.control import Viewer

with Viewer("ws://kiosk.local:5173/control") as viewer:
    story = viewer.dimension_index("story")
    viewer.set_dimension_value(story, 3)
```

That last call is the whole operation for a guided tour: moving the story
dimension is all a controller does, and the authored waypoints already fly the
camera, swap the dimension-bound overlays and cue the narration.

There is no second API to learn. The wire surface is the `LuxarApp` embedder
API — every public method except `dispose` and the handful that take callbacks,
plus `subscribe` / `unsubscribe` — and a lock test fails the build if a new
embedder method lands outside that policy. `dispose` is withheld because it
tears the viewer down in one frame with no way back, which on an exhibit means a
blank screen until someone power-cycles it.

`?control` is a bare flag: the hub rides on the app that served the page, so the
socket address is derived rather than typed, which keeps it working behind a
reverse proxy and under `luxar export`. An explicit `?control=<url>` is accepted
for a split origin but is same-origin only unless `?controlAllowCrossOrigin`
says otherwise — a crafted link would otherwise hand a stranger both the display
and its dataset URL. Without `--control-token`, browser sockets must be
same-host while non-browser clients remain open to anything that can reach the
hub. A valid token permits split-origin and reverse-proxied deployments and is
required on an untrusted network.

Two things were wrong on the way past and are now fixed: `switchDataset`
validated its URL not at all (the controller path now runs it through the same
validator `?src` gets), and the viewer only provisions picking when a
`selection` listener exists at load time, so a controller that subscribed later
would have received those events never and heard nothing about it.
