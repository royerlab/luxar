#### The PyPI docs link went nowhere, and the citation had no version

Three pieces of release metadata that only become visible on launch day, in
public, with no earlier signal. `[project.urls] Documentation` pointed at
`https://luxar.readthedocs.io/`, a host that 404s and never existed — there is
no Read the Docs configuration in the repo and the documentation is built onto
GitHub Pages — so the first release would have shipped a dead "Documentation"
button on the PyPI project page. It now points at the site that is actually
serving.

The PyPI sidebar now also links directly to the live demo gallery and hosted
viewer, so readers can try Luxar without first navigating through the source.

`CITATION.cff` carried neither `version:` nor `date-released:`, only a comment
asking someone to add them at launch, and `set_version.py` did not know the file
existed; the documented runbook would have left the citation describing an
unversioned work of no particular date. Both fields are now stamped from the
same CalVer, and a citation file missing them is an error rather than a silent
skip.

A writer without a checker only moves where the drift happens, so
`check_version_consistency.py` now treats the citation as a third
representation alongside `__version__` and the viewer `package.json` — and it
was confirmed to go red on a stale version, on a release date that disagrees
with an otherwise-correct version, and on missing fields, because a consistency
check that cannot fail is indistinguishable from no check. The three spellings
stay deliberately different — zero-padded CalVer for Python and the git tag,
leading zeros stripped for npm, the tag's form for the citation — so the gate
encodes that mapping rather than asserting equality.
