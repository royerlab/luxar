#### Defect-bearing lint rules are now ratcheted

Ruff's `flake8-bugbear` family and `RUF012` are enforced as a baseline-driven
ratchet by `scripts/check_lint_ratchet.py`, wired into `hatch run lint` and
`make check-all`. CI enforces the same check through its repository-level pytest.
Existing violations are tolerated via
`scripts/lint_baseline.json`; a file that newly breaks one of these rules, or
gains another violation of a rule it already breaks, fails the check.

These are the rules that describe silently-wrong code rather than untidy code:
mutable defaults shared across calls, closures capturing a loop variable by
reference, `warnings.warn` blaming the wrong line, `raise` inside `except`
dropping the cause, and `zip()` truncating to its shortest input. They could not
simply go into `[tool.ruff.lint] select` — there are 473 pre-existing
violations, 290 of them `zip()` without `strict=`, whose fix changes behaviour
(`strict=True` raises) and is therefore a decision per call site rather than a
mechanical sweep.

`B008` needed no baseline at all. All 83 findings were `typer.Option(...)` /
`typer.Argument(...)` in a parameter default — the documented Typer idiom,
evaluated once at import on purpose — so `extend-immutable-calls` now declares
those two calls immutable and the ratchet gates the rule at zero.

One live defect fell out of the measurement and is fixed: `stats/generate_stats.py`
passed `maxsplit` positionally to `re.split`, which Python 3.13 deprecates.
