#### The test suites are fast enough to run in the loop again

Both suites were slow for configuration reasons, not because the tests are heavy.
The TypeScript unit suite burned 468 s of CPU to run 38 s of test bodies, and the
Python suite ran locally without the two settings CI had already applied to
itself. `hatch run test` now takes 13 min 54 s instead of 79 min 19 s, and
`pnpm test --run` 22.5 s instead of 165 s, with identical or better pass counts —
nothing was deleted, skipped, or relaxed.

`ci.yml` had pinned `OMP_NUM_THREADS` and friends to one thread and passed
`-n 4` since the self-hosted runner landed, recording 45.5 min → 15.8 min for
the same tests and the same coverage. None of it reached `hatch run test`,
the documented pre-push gate, because `pyproject.toml` carried no `env-vars`
block and no script passed `-n`. Both are set now. `--dist loadfile` is
mandatory rather than incidental: plain `--dist load` rebuilds module-scoped
fixtures once per worker, which would undo the sharing that
`gsplats/tests/conftest.py` credits with taking that directory from ~14 min to
~1 min. Pinning also *fixed* eight subprocess-fitting tests that had been
failing on self-inflicted CPU oversubscription — Python failures went 11 to 3.
The pin is environment-wide, so it reaches real work run through hatch too — a
`--device cpu` fit, a demo, a benchmark. An explicitly exported value therefore
wins over it: `OMP_NUM_THREADS=16 MKL_NUM_THREADS=16 hatch run ...` runs at full
width, while a bare `hatch run` stays pinned.

On the TypeScript side `environment: 'jsdom'` applied to all 559 unit files
even though only 124 touch a document, and constructing one costs ~1.8 s of CPU
per file. `node` is the default now and the files that need a browser global carry a
`// @vitest-environment jsdom` docblock, derived empirically rather than
guessed — a slightly larger set than those 124, because a handful were pinned
for other browser globals rather than for a document. A missing docblock fails loudly with `ReferenceError` instead of
silently running in the wrong environment, and the two arrangements were proved
equivalent: on the same tree, node-default and jsdom-everywhere produce
identical test-ID sets with zero status differences across 11,521 tests.

Fixture staleness moved from mtime to a content digest. The old check compared
every fixture against the newest `.py` under `encoding/` and `io/` — including
the 52 test files there — so editing an unrelated Python test, rebasing, or
switching worktrees forced a full regeneration before a single TypeScript test
ran. Expectations remain coupled to fixture rebuilds, because
`generate_test_data.py` is not byte-reproducible and a rebuild from unchanged
inputs still invalidates them.

Two test bugs that blocked the parallelism are fixed along the way:
`available_port` scanned deterministically upward from 8000, so concurrent
workers collided, and the `test_server` fixture never shut its server down,
leaking a listening socket per test.

E2E screenshots, video and traces were being recorded for every passing test and
then discarded; they are failure-only now, and tests within a file run in
parallel with the resource-bound specs opting out. Finally, the documented
pre-commit checklist ran both suites twice — `check-static` and `check:static`
are test-free gates so `make test-all` is the only place tests execute, and
`make test-fast` is a new inner loop (~35 s scoped).
