#### `LUXAR_TRACEBACK=1` gets the traceback back out of a failed command

Seventeen CLI error handlers printed one line and exited. That is the right
default — a stack trace is noise when the cause is "file not found" — but there
was no way to opt out, so a genuine bug inside the library arrived as one line
with nowhere to go next. Eight of them discarded the exception chain as well,
two via `raise ... from None`, which erases the implicit context too.

Setting `LUXAR_TRACEBACK=1` now re-raises the original exception with its
traceback intact, and the one-line message says so, so it is discoverable at the
moment you need it:

```
❌ Error reading info for /tmp/notastore.luxar.zarr: No group found in store …
   (set LUXAR_TRACEBACK=1 and re-run for the full traceback)
```

An environment variable rather than a flag, because a Typer callback option has
to precede the subcommand — a poor shape for something you reach for after a
command has already failed. `LUXAR_TRACEBACK=1 luxar …` re-runs what you just
typed. `LUXAR_TRACEBACK=0` (and `false`/`no`/`off`) mean off, so exporting it
does not pin it on.

A separate group of about two dozen handlers already prints a traceback
unconditionally, which is the opposite complaint — a missing file should not come
with a stack trace. Making those opt-in too is a behaviour change for two dozen
commands and is left for its own change (#2553).
