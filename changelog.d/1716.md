#### Harden zipped-scene loading at the browser boundary

The `.luxar.zarr.zip` reader had no positive-path browser coverage because the
E2E fixture server ignored HTTP range requests. Playwright now uses the
range-capable fixture server, and the browser suite checks both STORED and
DEFLATE archives against the element counts of their directory twin.

That equivalence assertion prevents a false pass from an archive that reaches
viewer initialization while loading no geometry. ZIP64 archives beyond the
65,535-entry boundary and the producer-side `luxar serve` range contract are
covered as well.

The viewer guide now documents the hosting tradeoff: a single-file scene is
useful for distribution, but its first load costs more requests and bytes than
a directory store. Warm revisits remain cache-backed.
