#### The L2 OPFS cache gets a circuit breaker, and `?noOpfs` skips it outright (#1645)

A systemically stalled OPFS backend — the norm under automated Chromium —
used to cost the full ten-second operation timeout on every chunk,
serially, inflating scene readiness by half a minute and starving
downstream initialization (the E2E known-failing baseline traced to
this). The store now counts consecutive OPFS timeouts and, at
`cache.opfsTimeoutTripThreshold` (default 3) in a row with no settlement
between, disables the L2 tier for the session through the same
degradation path as an init failure: later operations are instant
no-ops, the in-memory tiers keep serving, and the data monitor shows the
existing `opfs-unavailable` badge. Any success or fast rejection resets
the count — the breaker targets stalls, not error rate. The store's
teardown metadata flush is now deadline-bounded too: a backend that
stalled just before teardown used to leave `dispose()` unresolved
indefinitely, hanging the dataset switch waiting behind it.

For environments that know their OPFS is hostile, the new `?noOpfs` URL
parameter skips the tier at construction (the deterministic sibling of
the breaker, mirroring `?noSliceCache`); a deliberate disable does not
raise the badge. The E2E suites that never assert L2 now pin it, which
un-stalls the long-standing known-failing families.
