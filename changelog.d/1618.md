#### A demo's local refit no longer erases itself on every launch

A gsplat demo whose hosted data was unreachable — an unpublished Zenodo record
and no `git lfs pull` — fell back to fitting locally and cached the result at
`~/.cache/luxar/<dataset>/<file>`, which is byte for byte the path the manifest
fetch resolves for that entry. On the next launch `ensure_dataset` checksummed
it against the manifest, found (inevitably) that a local fit does not match the
hosted file's sha256, quarantined it as `.corrupt`, and raised — so the demo
refit from scratch, every single time, leaving another quarantined file behind.
The "one-time; result is cached" message was never true, and for the cryo-EM
capsid it cost about eleven minutes a launch.

Locally computed artifacts now live in their own namespace inside the same cache
directory, `~/.cache/luxar/<dataset>/local/<file>`, resolved by the new
`luxar.utils.data_fetch.local_fit_path`. The fetch never looks there, so nothing
hashes it, quarantines it or overwrites it. Its companion
`load_local_fit_gsplats` reads that namespace back — returning `None`, rather
than raising, when a file is missing or unreadable, since the only recovery for
bytes with no checksum and no remote is the refit the caller can already do. The
one failure it does raise on is a multi-part store, which has no flat
`GSplatData` form at all: a rebuild would write the same unloadable shape and
refit on every launch, which is the very symptom being fixed. A demo that
publishes its own `LOCAL_FIT` constant reads through the path-based
`load_local_fit_gsplats_at` instead, so the constant its refit WRITES through is
also the one the door reads — the two must not be able to drift apart.
Every affected demo now consults it after the manifest fetch comes up empty and
before refitting, so the refit really is one-time; the eleven demos that used to
write over the manifest's paths (cryo-EM virus, CT TotalSegmentator and its
labels sidecar, Milky Way dust, DAPI nuclei, OpenCell MAP4, cells3d, blastocyst
multichannel, both kidney demos, CMU-1 pathology, and the Visible Human head)
were migrated together. Ten of the eleven were live bugs. The Visible Human head
is the exception and is called out as such in its own source: nothing in that
demo routes its dataset through the manifest, so no checksum ever ran over its
two names and its refit really was reused — the hazard there is LATENT, and the
namespace is separated now because the day the demo joins the manifest path is a
one-line change that would otherwise reintroduce the every-launch refit in
silence. `luxar demo cache clear` now classifies anything under
`local/` as a computed artifact, so `--no-computed` spares these refits instead
of sweeping them away as if they were re-downloadable files, and labels cache
entries by their path relative to the cache dir so `local/x.zip` is
distinguishable from the fetched `x.zip` beside it. The classification keys on
the `local/` path alone: a demo that still writes an expensive artifact straight
into its cache dir (the NEXRAD per-frame fits, the C. elegans preprocessed
frames) is still counted as a download, which is deliberate — those names
collide with no pinned manifest entry, so they were never exposed to the
quarantine this change is about.

All twelve demos that fall back to a local rebuild when a manifest fetch comes up
empty now catch narrowly: eleven of them the new `DatasetUnavailable` rather than
a bare `FileNotFoundError`, and the NEXRAD supercell that plus the new
`BundleMemberNotFound`. Only those conditions mean "these bytes are not
obtainable from anywhere yet", and only they may be answered with a multi-minute
refit; an unknown requested file name, a missing packaged manifest, a dataset key
the manifest does not carry and an in-repo copy that fails its pinned sha256 are
faults, and now propagate instead of being disguised as a routine rebuild. The
NEXRAD case needed its own error rather than a swap: `load_dataset_bundle` raises
a plain `FileNotFoundError` both for a bundle the manifest does not list (a
fault) and for a per-frame member the bundle does not contain — and the latter is
routine there, because those member names carry the run's `--dbz-floor` /
`--splats` / `--grid-m`, so a non-default value legitimately asks the shipped
bundle for frames it cannot hold. The two are now distinguishable.

One consequence is worth stating plainly, because it is a new capability rather
than a fix: CMU-1 pathology used to CRASH when its dataset could not be reached,
and now falls through to the ~169 MB SVS download and a three-channel tiled fit
over the full 46,000 x 32,914 image — the same unattended work `--recompute`
does, cached afterwards in the local-fit namespace. Its module docstring says so.

An AST gate over every `demo_*.py` keeps the boundary: a demo that hands a
`~/.cache/luxar/<zenodo dataset>/<pinned file>` path to anything but a known
reader now fails the test suite, with the shapes the demos actually use
(a module-level constant join, an f-string built in a per-channel loop, an
indexed file list, a sidecar written by a demo-local helper, a second name the
path is laundered through, a write through a method on the path itself) each
covered by its own self-test. It resolves the cache dir by four spellings, not
one — the literal `Path.home()` chain plus a join onto `DEMO_CACHE_ROOT` /
`_DEFAULT_CACHE_ROOT`, directly or through another name. Crucially, neither half
of a join may go unsettled: a pinned file name joined to a directory the analysis
cannot identify is reported as a blind spot instead of passing green, and so is
the mirror case — a basename it cannot resolve (a `zip`-bound loop variable, an
f-string behind one hop, a function parameter) joined onto a directory it has
PROVED is the manifest's own, which is the stronger evidence of the two and used
to be the quieter answer. A blind spot is a reviewable state, not a failure, and
the one the shipped demos have (DESI's source catalogs, named out of a nested
dict) is enumerated with its reason. What the gate still cannot see is written
down where it can be checked, and pinned by tests: `d.joinpath(name)` is read
like `d / name`, `os.path.join` and `.with_name()` are not. The one write it
permits by construction — the Visible Human head promoting its shipped git-LFS
pair into the manifest's own path, bytes that DO match the pinned sha256 — now
requires the source to be rooted at `__file__`, so an arbitrary local directory
with `data` in its name cannot launder a fit through the exemption, and it
recognises an aliased `from pathlib import Path as P` rather than reporting the
legitimate copy. Verified by running the analysis over the eleven pre-fix
sources, where it fires on all eleven.
