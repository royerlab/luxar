#### The pick pass no longer depends on which fragment entry point three builds first (#1683)

`colorNode` and `depthNode` are two independent fragment entry points of one
NodeMaterial, and a TSL value materialised with `.toVar()` is assigned wherever
three first BUILDS it — which entry point that is is not part of three's API. The
gsplat and mesh pick factories both share their whole fragment chain between the
two (the Mahalanobis/intensity/brightness chain on gsplats, coverage/near-fade/
brightness on mesh) and both have a BRANCHING `depthNode`, the `uSurfaceDepth`
convention selector. When the depth flow is built first, that branch becomes the
first build site: three lowers it to a real `if`/`else` and the shared assignments
land inside one arm, while every top-level reader — both `Discard` conditions and
the output vec4 — reads a variable that was never assigned, i.e. `0`. The result is
not a subtle artefact: every pick fragment discards, the pick buffer comes back
empty, and hover and click stop working entirely on the WebGPU path.

Each factory now assigns every value the two entry points share in a `'void'`-typed
`Fn` prologue invoked as the FIRST statement of both of them, so the assignments are
emitted in unconditional top-level flow whichever flow three emits first. On mesh
that includes the alpha-cutout flag, read by both the prologue's brightness select and
`colorNode`'s cutout discard. Left free-standing it was still materialised — three
gives a select's condition its own `bool` — so it was never duplicated, but its first
build site moves into the arm under the depth-first order just like the rest, and then
the top-level cutout discard reads `false` and stops discarding anything at all.
Assigning it in the prologue brings the last shared value under the guard too.
The three sibling pick factories (points, lines, capsule lines) keep their shared
brightness var: their
`depthNode` is branchless, so the assignment lands at top level either way — each
one now says so at the site, together with the note that adding a branch there needs
the same prologue treatment.

The gsplat prologue's fragcoord reconstruction and its centre delta are `.toVar()`s
too now, like every value around them, so the whole prologue is a statement list
rather than one subexpression re-expanded at each of its six uses. Same arithmetic,
shorter generated fragment (its snapshot moves accordingly).

The runtime pin does not move here — `three` stays at `~0.184.0`, whose colour-first
build order was never affected — so nothing about the shipped renderer changes with
this fix. What it removes is the blocker in front of the r185 bump, where the order
flip is what turned a latent hazard into a dead pick pass. (That bump followed
separately, and the runtime is now on r185.)

A codegen guard comes with it, over all four pick shaders that expose a named shared
var (gsplat, mesh, line, capsule line). The TSL snapshot spec now parses the generated
pick fragment's `main()` body, tracks the brace depth of every line, and asserts two
things: every assignment sits at depth 0, and the first READ comes after the first
assignment that is not the dead `NAME = 0.0;` initialiser three emits for a
`float(0.0).toVar(name)` declaration. It is keyed on the explicit `.toVar('name')`
names rather than three's generated `nodeVarN` numbering, and fails with the remedy
(compute it in the fragment prologue).

The two halves have different reach, and which one is live depends on the runtime
revision. At r184 the read-order half is the live one: dropping the
`fragmentPrologue()` call, or moving a reader above it, leaves the value holding its
declaration default and the assertion says so. The brace-depth half is the inert one
there — colour-first order builds even the pre-fix free-standing `.toVar()`s at top
level — and it is the one that goes live once the runtime moves to r185, which trades
the two around rather than arming both. Both run in the FULL E2E suite
(`make test-e2e`), not in the mobile-only `e2e-tests` job or the narrow
`tsl-parity` job, which deliberately excludes the codegen snapshot. The mesh spec's
TSL house rule grew a third clause to match.
