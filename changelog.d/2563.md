#### Bloom renders as a glow again on the WebGPU renderer

On the opt-in WebGPU renderer, bloom came out as a flat dim wash rather than a
glow. The bloom pyramid's upsample pass accumulates each smaller mip into the
larger one by drawing it with additive blending, and that blend is the whole
accumulation mechanism — without it every upsample overwrote its destination mip
and only the last, weakest contribution survived.

The cause was in `buildMaterial`, the helper both backends construct their
post-processing materials through: the WebGPU branch forwarded only the uniform
table to the TSL factory and discarded the rest of the requested state, so the
returned material kept its default `NormalBlending` while the WebGL branch
honoured the `AdditiveBlending` the bloom chain asked for. The render state
(`blending`, `depthTest`, `depthWrite`, `transparent`, `toneMapped`, `side`) is
now resolved once and applied on both branches, which fixes bloom and closes the
same trap for every material the WebGPU port gains next. The other five keys were
silently dropped too, and were harmless only by coincidence: the bloom and FXAA
factories happen to set matching `depthTest`, `depthWrite` and `transparent` on
themselves, `side` was never set by any of them but its material default already
matched, and `toneMapped` is not read on that backend at all.
