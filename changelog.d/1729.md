#### A preset-less content fit is near-lossless again, as it always claimed to be

`gsplat fit --tiling content` without a `--preset` fitted every box at
`cull_retention=0.95`, discarding the bottom 5% of cumulative amplitude after each
box, while the code sitting right there said 0.999. The line meant to install that
default was `fk.setdefault("cull_retention", 0.999)`, and it could never fire:
`load_fit_config` starts from the defaults harvested off `fit_gaussian_splats`'s own
signature, which include `cull_retention=0.95`, so the key was always present by the
time the planner looked. Only the preset-less invocation was affected — every preset
sets 0.999 explicitly — which is exactly the invocation a first content fit tends to
be.

Content tiling keeps its own near-lossless retention, and now actually gets it. Why
content specifically: the library-level sibling `fit_planned` already declared 0.999
for the boxes it fits, so the dead line in the CLI planner was the CLI half of an
intent that already existed downstream — the two halves now share one constant,
`luxar.gsplats.planner.CONTENT_CULL_RETENTION`, and cannot drift apart again. And
content is the `--cal`-driven path, so it is where that 0.95 — one half of the false
`signal_limited` curve `gsplat cal` used to report — is most in play. A per-box cull
also compounds, the merged store losing the weakest splats of every box rather than
of the volume, but that argument does not single content out: `--tiling uniform`'s
default partition merge culls each tile independently too (only its `--flat` merge
culls once, globally), and it stays at 0.95 on purpose. Only the content path moves
here.

The mechanism is a new per-command defaults layer in `load_fit_config`, sitting
directly above the harvested function defaults: the priority chain is now
`CLI flags > YAML config > preset > command defaults > function defaults`. So
`--preset`, a `cull_retention:` in a `--config` and `--cull-retention` all still win
over it — including `--cull-retention 0`, the "keep every splat" escape hatch — and
only the fitter's 0.95 is displaced. The `-j N` box workers resolve the same value
through the same code path, so parallel and sequential content fits cannot diverge.
Nothing else moves: a whole-volume fit (`--tiling none`) and `--tiling uniform` still
fall through to the documented 0.95.
