#### Quality metrics and volume-reference commands now use the fit's own basis

A fit reconstructs `V - image_min`, never `V`: the level normalization subtracted — which
absorbs any background floor — is deliberately never added back. Several commands handed a
raw volume to a fitted dataset anyway, comparing two different quantities.

The clearest symptom was in the numbers a fit publishes about itself. Scored against a raw
reference, a fit is charged for the pedestal it correctly refused to represent, and the
penalty grows with the floor — so raising the floor *lowers* the reported PSNR on identical
data. Measured on a synthetic stack: **23.2 dB over a 50-count pedestal versus −6.0 dB over
a 4000-count one**, a 29 dB swing that is entirely artifact. That inverts comparisons, and
`psnr_db`/`ssim`/`mse` are persisted into the store and printed by `gsplat info`, so the
wrong number is the published one.

Fixed at every site that crosses the basis boundary:

- **The fit's own metrics** are scored against `clip(V - image_min, 0, None)`. The PSNR
  `data_range` and the `rel_l2` denominator follow the reference, so their inflation goes
  with it.
- **Tiled and batch merged-quality metrics** use the merged normalization level for both
  flat and partition outputs, so large-volume fits publish scores on the same basis.
- **`gsplat compare`** loads the dataset with stats (previously `include_stats=False`, which
  made the stored level structurally unreachable), shifts the reference, and reports which
  basis it used. `--image-min` overrides it for stores fitted before the level was recorded.
- **`cull --target`** shifts the target before computing the error budget, which was
  otherwise biased toward retaining whichever splats reproduce background.
- **`lod --refine volume`** re-fits each coarse level on the ladder's basis instead of
  re-estimating a background from the raw volume, which could leave a refined level on a
  different basis from its siblings. Its persisted `mse_seed`/`mse_refit` stop carrying a
  pedestal offset too.
- **`gsplat render`**'s docstring no longer advertises its output as directly comparable to
  the original. Background-relative output is correct by design; only the claim was wrong.

Where a store records no level, every site says so and leaves behaviour unchanged rather
than guessing one — absence is ordinary rather than exceptional, since merging several
fits drops any normalization key the inputs disagree on. A recorded level of exactly zero
is treated as a real answer, not a missing one: a tiled fit pins every tile at
`image_min = 0` deliberately, and such a ladder's basis IS the raw volume, so the re-fit
must not go looking for a background that level denies. `compare --image-min` is validated
to the same standard as a stored level, since a negative one would shift the reference the
wrong way and score against the wrong thing silently.

The conversion itself is a single shared helper, so the sites cannot drift apart.
