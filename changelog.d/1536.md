#### Two shapes of doc drift: a CLI flag that never existed, and mesh's reveal ladder (#1536)

`docs/guides/user/CLI_REFERENCE.md` told readers to run `luxar mesh lod -o out`,
but the command's output is a positional argument, not a `-o` option — copying
the example got Click's "No such option: -o". A new drift-guard test now
checks every option spelling named INLINE within a per-command section of the
CLI reference against the live Typer app's declared options — a leaf section
strictly, a group section against the union of its subcommands' — not just the
command paths the existing guard already covered. A fenced example block's
catalog lines are a separate, deliberately unchecked surface: they legitimately
cross-reference another command's flags, and the guard does not follow them.

Several other passages — the mesh spec, this package's mesh README, the
front-page README, the architecture concept doc, `CHANGELOG.md`, `CLAUDE.md`,
the viewer's `data/README.md`, and the Zarr writer/protocol docstrings — still
asserted mesh has no additive ladder at all, or no progressive loading, which
stopped being true once mesh gained a *reveal* ladder
(`add_mesh(additive_lod={"method": "radial"})`, #1503/#1515): a growing
surface, not a coarsening one, so a prefix of the index buffer stays valid the
way a prefix of an arbitrarily-ordered one never could. Each passage is
corrected to say a reveal ladder exists and substitutive LOD (decimation)
ships, while an additive ladder over an *arbitrary* order and `volumetric`
blending are still refused — the distinction, and the reason for it, are
unchanged.
