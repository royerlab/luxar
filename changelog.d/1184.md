#### In-repo gsplat benchmarks now pin `floor="none"` instead of inheriting `auto`

The three in-repo fitting benchmarks — `scripts/benchmark_progressive_psnr.py`,
`scripts/benchmarks/benchmark_fitting_pareto.py` and
`scripts/benchmarks/benchmark_progressive_pareto.py` — called the fitters without a
`floor=` argument and so inherited the shipped default `floor="auto"`, a
histogram-mode background pedestal estimate that is subtracted from the volume
before fitting. All three then scored PSNR/SSIM of the reconstruction against the
*raw, un-floored* volume. That is a mixed basis: the fit is penalised for correctly
dropping a pedestal the reference still carries, and the reported number moves
silently whenever the floor estimator changes. How large that penalty is depends
strongly on the dataset: the 2026-07-12 measurement recorded in
`docs/guides/developer/BENCHMARK_FLOOR_DECISION.md` found −5.86 dB on kidney_dapi
(31.77 → 25.91) but +0.01 dB on blastocyst — near zero where
there is little pedestal to remove. All three print a `METRIC=` line for
autoresearch extraction, and the two Pareto harnesses additionally return their
dominance verdict as an exit code; every one of those signals was exposed to the
drift. Every fit call in those harnesses — including the progressive Pareto
warm-up, so it exercises
the same code path as the fits it warms up for — now pins `floor="none"`, matching
the repo/manuscript convention for a benchmark scored against a raw reference.

No baseline is invalidated *in the repo* — neither Pareto baseline file is
committed — but a machine that has run either Pareto benchmark before still holds
one on disk, measured under `floor="auto"`. Both harnesses demand that every axis
be at least as good as the baseline, so comparing a `floor="none"` run against it
can print `PARETO: NOT DOMINANT` and exit 1 for a change that regressed nothing.
Delete any local `scripts/benchmarks/data/*baseline*.json` once after this change;
the next run has no baseline and becomes the new one.

The shipped default is unchanged and deliberately so — `gsplat fit`/`cal` keep
`--floor auto`, which is the right behaviour for real use, since a constant
background pedestal is not signal. A new source guard,
`packages/luxar/src/luxar/tests/test_benchmark_floor_pin.py`, keeps the two apart:
it parses every `*.py` under `scripts/` with `ast` and requires each call to a
module-level gsplat fitting function to declare its floor at the call site. The
public `fit_tiled_gaussian_splats` alias is listed alongside `fit_tiled`, and
local `import ... as` aliases are resolved within the file, so neither spelling
nor renaming on import evades the rule (a fitter passed around as a *value* —
`functools.partial` and friends — still would; that would need dataflow analysis
the guard deliberately does not have). Declaring means a `floor=` keyword, or a
kwargs dict carrying the key that is visible at the call site — an inline
`**{"floor": ...}` or a module-level `FIT_KWARGS = dict(..., floor=...)`, the
idiom the luxar-paper harnesses pin with — while an opaque `**kwargs` forward is
still an offender. Also listed are the two worker-argv builders,
`build_worker_cmd` and `_default_worker_cmd_builder`: each omits `--floor` from
the tile worker's argv when it is `None`, leaving the worker on `auto`, so a
future harness tile-fitting through them would be this same bug. It asks for a
*declared* basis rather than a particular value, so a harness that genuinely wants
the shipped suppression writes `floor="auto"` and passes. `fit_tiled_parallel`
itself stays unlisted for the opposite reason: it has no `floor` parameter at all,
so demanding one there would order an author to write a `TypeError` (same for
`fit_planned_parallel`). `fit_planned` *is* listed: it collects `**fit_kwargs` and
forwards them to a per-box `fit_gaussian_splats`, so a `floor=` at its call site
is both visible to the gate and honoured at fit time — and it needs the
declaration more than most, since an unpinned `auto` there is re-estimated
against every box crop separately. There is
deliberately no file allow-list: the
requirement is satisfiable entirely within the file that adds the call, so a
harness written on one branch can never redden the guard after merging with an
unrelated branch — and for that same cross-branch reason an unparseable file
becomes a finding that says the floor pin is not what is broken, rather than a
traceback out of the gate. Separately, it parses the raw bytes so that Python's
own source-encoding rules apply (a BOM or a PEP 263 encoding cookie is handled,
as in `scripts/check_documentation.py`). The gate's own docstring records what an
AST call-name check cannot see — `GaussianSplatFitter.fit`, argv-driven fits such
as `luxar gsplat cal` (self-consistent, so it needs no pin, and it takes its spec
inside a `fit_kwargs` *dict argument* a keyword check cannot read either), a floor
passed positionally (deliberately
still reported: "declared" means a reader can see which argument it is), and the
demos outside `scripts/` whose printed PSNR nothing gates on.
