#### Ratchet TypeScript correctness and complexity debt

Viewer linting now rejects new floating or misused promises, invalid awaits,
unsafe implicit stringification, and production functions that exceed the
complexity, size, nesting, or parameter limits. Existing findings are recorded
as per-file counts in ESLint's native suppressions file, so new debt fails CI
without requiring the current backlog to be fixed in the same change.

Paying down a finding now fails lint until the suppressions file is pruned. Run
`pnpm lint:prune` to tighten the recorded count and commit the updated baseline
with the cleanup.
