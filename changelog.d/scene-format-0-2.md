#### Scene format 0.2: a self-identifying root header and one version-check rule

A compiled `.luxar.zarr` now stamps `format_version: "0.2"`, `format_type: "luxar_zarr"` and `luxar_software_version` (the `luxar.__version__` that wrote it) on its root, mirroring the standalone gsplats header so a reader can tell the two store kinds apart from the root attrs alone. The 0.1 key `luxar_version` is no longer written but stays a read fallback everywhere, so every published 0.1 store — the DESI Zenodo record included — loads unchanged. The software stamp is provenance only: both content hashers (the compile-time walk and `luxar optimize`'s streaming twin) exclude it through one shared `HASH_EXCLUDED_ATTRS`, so two releases compiling the same scene agree on `content_hash` and a restamp never cold-starts a viewer's cache.

Format-version checking is now one rule, applied identically to scenes and gsplats stores in Python (`luxar.typing_utils.format_version`) and the viewer (`data/format-version.ts`), pinned by a shared case table in both test suites: a supported version loads silently, a same-major newer minor loads with a warning, and an older-unsupported, newer-major or unparsable version is refused with the version and the remedy named. The viewer, which previously never checked a scene's version at all, now surfaces a refusal on the error overlay; the gsplats readers, which used to hard-refuse any unlisted version, now warn-and-load on a newer minor. The reserved `0.3` slot is gone from the contract — a newer minor is policy, not a pre-declared entry.

The cross-language format contract (`format-contract/contract.yaml`) also absorbs the on-disk vocabularies that were hand-kept in two languages with a "keep in step" comment: LOD selectors, blending modes, tone mappings, built-in colormap names, physical units, ordering methods, line join styles and line types, `nd_transform` entry keys, the per-dimension attr keys, and the writer's render-attribute allowlist. Each is now one YAML list projected to a Python `Literal`/tuple and a TypeScript union/const array, with lock tests (and type-level checks in the viewer) on every hand-written consumer, and the generator is table-driven so a new vocabulary is one row.
