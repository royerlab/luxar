#### `batch-fit run` gains `--calibration-samples`, and `submit`'s `--gpus` becomes `--gpus-per-task`

`batch-fit run` and `batch-fit submit` plan the same job and differ only in who
executes the tasks, but each mapped its flags onto the planner's config objects in
its own code. The copies drifted: `--calibration-samples` was declared on `submit`
only, while the local path consumes it — a local `--denoise` run with a deferred
percentile floor always calibrated `h` on 5 timepoints, with no way to ask for more.
The flag now exists on both, with the same default, so nothing changes unless you
set it.

`--gpus` meant two different things on the two commands: on `run` it selects which
local devices to use (`auto` | `all` | `cpu` | `0,1,3`), on `submit` it was a count
of GPUs to request per Slurm task. So `--gpus 2` meant "use card #2" on one and "two
GPUs per task" on the other, and `--gpus auto` was a parse error on `submit`. The
Slurm one is now `--gpus-per-task`, which is also the directive it generates. `run`'s
`--gpus` is unchanged.

Both commands now build their configs through one shared mapper, and a new agreement
test fails if a second mapping site appears, if a flag reaches one command and not
the other, or if the two disagree on a shared default.
