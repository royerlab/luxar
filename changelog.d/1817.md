#### Numeric NGFF dataset paths resolve consistently

The declared-path rule now also decides what a non-string OME-Zarr/NGFF
`datasets[*].path` may name: real numeric scalars are coerced, while every other
non-string value names nothing. Out-of-spec producers that serialize numeric
level names as numbers therefore retain their declared axes and voxel size,
while a numeric declaration that still cannot resolve is reported instead of
being dropped silently. Malformed values do not become plausible array names
such as ``None`` or ``[]``.

This can change which array and axes an all-numeric malformed pyramid selects.
Re-plan a `batch-fit` run that uses such a source rather than resuming an existing
plan. When numeric and string aliases name the same level, declaration order is
authoritative: the fix makes lookup and metadata agree; it does not prefer the
string declaration.
