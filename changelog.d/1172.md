#### A warm-started re-fit can now say its amplitudes are background-relative (#1172)

`preprocess_data` rescales pre-initialized amplitudes into the optimizer's
normalized `[0, 1]` scale with `(a - image_min) / intensity_range`. That is right
for amplitudes sampled off the raw volume, but wrong for amplitudes that come out
of a *previous* fit: `finalize_results` multiplies the normalized amplitudes by
`intensity_range` and deliberately never adds `image_min` back, so they are
already background-relative. With floor suppression active (`floor="auto"` is the
default) `image_min` *is* the applied floor, so a warm start had the pedestal
removed a second time and every seed dimmer than the floor was initialized to
exactly `0` — the re-fit restarted from a hole instead of from the seed. The live
caller is `--refine volume` (`volume_refit`), which seeds with a previous fit's
output and passes no `floor`, so it inherits the `"auto"` default.
`fit_progressive_gsplats` never reaches that door at all: it pops any
caller-supplied `seeds` and passes an int count per pass, so
`isinstance(seeds, GSplatData)` is never true there — whatever the floor. (It
additionally subtracts the floor from the volume up front and forces
`floor="none"` on every pass, which is a real invariant of that path but not the
reason it is immune.)

The convention cannot be sniffed, so the caller declares it. `seeds=GSplatData`
is one door with two users: a warm start from a fit, and `generate_seeds()`
output in the documented explicit-seeding workflow
(`fit_gaussian_splats(V, seeds=generate_seeds(V))`), whose amplitudes are
raw-image-sampled. A bare `GSplatData` records no provenance, and guessing either
way silently breaks the other user — treating everything as a fit's output starts
explicit seeds too bright by `floor / intensity_range`. `fit_gaussian_splats` and
`FitConfig` therefore gained `seed_amps_background_relative`, defaulting to
`False` = raw-image-sampled, so the explicit-seeding path and every other
existing caller are unchanged. `volume_refit` passes `True`, and
`preprocess_data` divides by `intensity_range` alone when it is set. Internally
the flag rides on the seed-generation context, set at the two call sites of the
shared extractor rather than inside it: the seeding path samples the still-raw
volume itself, so it is unambiguously `False` there.

Fixed alongside, since the empty-seed edge case came up while working on this:
`fit_gaussian_splats` crashed with `KeyError: 'time_seconds'` whenever a fit
produced no seed candidates at all — a signal-free tile, or an empty warm start.
`GaussianSplatFitter.fit` deliberately short-circuits that case and returns an
empty result with an empty `stats` dict, but the `verbose` summary (and `verbose`
defaults to `True`) indexed the timing fields regardless. It now reports the
empty result instead.

One approximation remains, deliberately: a re-fit resolves its own
`intensity_range`, which need not be byte-identical to the one the seed was
produced under, so a warm start is exact only when both fits resolve the same
normalization. That is a property of re-normalizing at all, not of this fix.
