#### Mesh and shading are documented

`luxar.mesh` and `luxar.shading` are public packages — both declare `__all__` —
that had no presence in the API reference at all, while `docs/api/cli.rst`
carried thirteen `automodule` entries for CLI internals. Both now have pages,
listed in the index toctree and in a new "Geometry & Appearance" group in the
Packages Overview. `bake_ambient_occlusion`, the sanctioned way to make emissive
geometry read as three-dimensional, is findable.

The `luxar mesh` command group is documented for the first time. It has shipped
`import` and `lod` for some time, and the string `luxar mesh` appeared nowhere
in CLAUDE.md; the root README covered the Python mesh API thoroughly but never
mentioned that a classical mesh file could be imported at all. The two LOD
recipes are spelled out, because they are not interchangeable: `levels`
decimates into coarse levels that replace one another, while `reveal` writes an
additive ladder of disjoint face groups. A surface has no coarse prefix, which
is why a mesh cannot have both.

A new test keeps this from recurring: every top-level `luxar.*` package that
declares `__all__` must be named by an autodoc directive somewhere under
`docs/`. Both sides are derived from the tree rather than listed by hand, so a
new public package cannot be added without a page.

Separately, `grimp` is now pinned below 3.16. It is import-linter's Rust graph
engine, and 3.16 dropped the macOS arm64 wheel for standard CPython 3.14, so the
hatch env tried to build it from source and failed on any rustc older than 1.94
— with an error naming ruff's crates rather than grimp's. Linux is unaffected at
every version, so this reached only macOS developers.
