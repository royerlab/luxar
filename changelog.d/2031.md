#### Measure the demo archives once, commit the figures, render from those

`gen_zenodo_records.py` read each archive's `fitting/` stamps at render time. That
worked while the archives lived in the repository, and the migration to Zenodo is
removing them — so the text could only be generated on a machine holding ~400 MB
of demo data, and on a partial checkout it reported "no PSNR" for archives whose
hosted copies are fully stamped. Publishing an absent figure for data that has
one is the failure the generator exists to prevent, occurring in its own output.

Measurement is now separate from rendering. `--refresh` reads whatever archives
are present and writes `scripts/demo_archive_characteristics.json`; rendering
reads that. It is 16 KB of committed text, so it survives payload removal, needs
neither network nor git-LFS content, and the next refit re-stamps it as part of
the upload step.

Two things the separation made necessary, both learned by measuring rather than
reasoning. `--archives-root` searches a staging tree first, because the repo and
cache copies are the PRE-REFIT generation for every dataset the campaign touched:
8 of 27 local archives carry a PSNR and **none** carry a foreground PSNR, while
the staged generation gives 17 of 18 with both. And a measurement taken from the
staged copies outranks one taken locally, because without that a later local
`--refresh` silently replaces every refitted dataset's figures with the stale
ones — the staleness this file exists to end, reintroduced by its own tool.

Each entry records the `measured_sha256` it came from, so `--check` can now say
when a figure was measured from bytes the manifest no longer pins. That is the
drift a refit causes, and the hand-written descriptions had no guard against it.

Measured effect: archives that would publish an incomplete row fall from 28 to
18, and 17 rows across the three records gain both a PSNR and a foreground PSNR
where they previously printed a dash.
