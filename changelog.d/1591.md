#### A scene's `cinematic_mode` now actually applies the cinematic preset

`ViewerConfig(cinematic_mode=True)` was accepted, serialized, and mapped straight
through to `RenderingSettings.cinematicMode` — a flag nothing downstream acted on.
The preset (ACES, subtle wide bloom, detector noise, vignette, 35 mm chromatic lens
+ FOV) was only ever applied by the C-key/rail toggle, so an authored scene rendered
with none of it, and the panel checkbox was then recomputed from the very effects
that had never been enabled.

The preset values moved from `ui/rendering-controls/cinematic-mode.ts` down into
`config/cinematic-preset.ts` (the UI module re-exports them, so nothing else
changed), and the zarr config bridge now expands them at load time for every preset
key the scene did not set explicitly. An author-set key always wins, so
`cinematic_mode=True` alongside `bloom_strength=0.9` gives the film look with your
bloom. Expansion happens in `extractRenderingOverrides`, so both first-time scene
load and reset-to-defaults get it. Only a strict `True` triggers it — a `false`,
`null`, or non-boolean value expands nothing.
