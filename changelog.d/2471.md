#### Coverage gates that actually gate

Both coverage floors had drifted far enough below the measured numbers to stop
enforcing anything: Python sat at `fail_under = 80` against 92% measured, and the
viewer at 71/71/74/61 against 88/87/85/82. The viewer could have lost a third of
its tests and stayed green.

Three measurement defects had to be fixed before the floors could be set honestly.
The Python `exclude_lines` entries are regexes searched against every physical
line, and a hit inside a multi-line statement is attributed to that statement's
first line — so the unanchored `"pass"` deleted whole function bodies from the
report wherever a `passes` substring or a `*_per_pass` parameter name appeared,
76 files and roughly 1,102 statements of them. It was hiding well-tested code
rather than thin code, which is why nobody noticed. On the viewer side, vitest 4
removed `coverage.all` and `include` defaults to "files some test imported",
leaving 45 source files outside every threshold — so adding an untested module
could raise the reported number. And a vitest glob threshold matching zero files
reports `pct: "Unknown"`, which compares false against any floor and passes
silently, turning a renamed directory into a gate that inspects nothing.

Floors are now Python 89 and viewer 86/85/82/80, plus thirteen per-subtree floors
so a healthy subtree cannot be dragged down by the global average. Because a floor
set once decays, `check-coverage-slack.mjs` now fails `check:ci` whenever any floor
drifts more than three points under measured, rejects empty globs, and prints the
exact replacement value; thresholds live in a single module shared by the config
and the guard so the two cannot disagree.

A narrow `tsl-parity` job also puts the TSL/GLSL shader parity spec into CI for the
first time. Roughly five thousand lines of the rendering cone were counted in the
coverage metric while being gated by nothing.
