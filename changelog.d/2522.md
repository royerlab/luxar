#### The browser support matrix says what was measured

Two READMEs listed four browsers as fully supported, with version floors, while
the Playwright config declared a single project — Firefox and WebKit were
commented out, so the claim had never been run even once.

It has now been run. Chromium, Firefox and WebKit all pass the E2E smoke subset,
but WebKit's OPFS store fails its init probe, so it renders correctly while
running **without the on-disk chunk cache** — nothing persists between sessions.
That is exactly the kind of difference a "supported" column hides, and it
matters most for the large datasets the old table was recommending a browser
for.

The version floors are gone: there is no `browserslist` and the build targets
`esnext`, so no floor follows from the toolchain and the numbers were never
derived from anything. The claim that Firefox decompresses WebAssembly twice as
fast is gone too — it appeared exactly once in the repository with no benchmark
behind it, and a specific number nobody measured reads as though somebody did.

Firefox and WebKit are now real Playwright projects rather than comments,
opt-in behind `LUXAR_E2E_BROWSERS=all` so the default suite still runs one
engine. `pnpm test:e2e:browsers` reproduces the measurement, and a new check
refuses to let either README name an engine the suite cannot run, or state a
version floor.

`luxar export --native` now names its `make build-launchers` prerequisite in the
CLI reference.
