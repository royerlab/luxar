#### Cross-node depth ordering, opt-in

Two spatially overlapping order-dependent nodes — points, lines or Gaussian
splats in `normal` or `volumetric` blending — can now composite correctly against
each other. Previously the whole of one drew before the whole of the other, and
for two interpenetrating objects no whole-object order is correct from every
viewpoint at all, so the ordering error was unavoidable rather than merely
approximate.

Off by default. Enable with `?depthShards=N` (a per-node split count, e.g.
`?depthShards=16`); `?depthShards=0` pins the previous draw order for
deterministic runs. Config lives in `config.depthShards`.

Only a node whose bounds overlap a *foreign* node is split, which is what keeps
the feature nearly free on a normal scene: the cost was measured, and it is
dominated by nodes alternating in the draw sequence rather than by the number of
draws — +5.5 ms at 128 interleaved draws versus +6.4 ms at 512, on two million
splats. So the split count is generous and the gate is coarse; a draw-count
ceiling bounds the smaller term that does scale with draws. Parts of one spatial
partition never qualify against each other, since they are already ordered
exactly.

One existing behaviour changes when the feature is on. A large node containing a
small embedded one used to be forced to draw first, because with one draw per
node no order was right and drawing the container last erased the embedded node.
When both are split that compromise is no longer needed — their ranges interleave
at their true depths — so it is dropped. It also had to be: two co-extensive
interpenetrating nodes have near-identical bounds, so whichever was a hair larger
"contained" the other and the rule forced exactly the strict ordering this
feature exists to remove. The compromise still applies when only one of the two
is split.
