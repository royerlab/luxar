#### Redistributed bundles now carry their third-party licence notices

The compiled viewer is redistributed four ways — the npm package, the wheel's
`luxar/_viewer_dist`, `luxar export` folders and the native launcher bundles —
and none of them carried a notice for any of the third-party code inside. The
production build emitted nothing because it runs no plugins, so only Luxar's own
BSD-3 licence existed anywhere in the tree. MIT, Apache-2.0, MPL-2.0 and BSD all
require their notices to accompany a binary redistribution.

The build now generates `THIRD_PARTY_LICENSES.txt` from what it actually
consumes: the pnpm production closure, the cargo build graph of the WASM module,
and the colormap generator's own tables. Nothing is listed by hand, so a new
dependency cannot ship without its notice, and the generator refuses to write a
file it cannot complete rather than emit a plausible-looking partial one. Luxar's
own licence is embedded in it, because an export folder travels on its own.

`luxar export` now refuses to produce a folder whose notices are missing, rather
than warning: the folder otherwise looks complete to whoever receives it.

Separately, `scripts/generate_builtin_colormaps.py` no longer deletes four
shipped colormaps. `builtins.py` credits it as the generator, but running it
dropped `orange`, `bop_blue`, `bop_orange` and `bop_purple` from both the Python
and the TypeScript output without saying so — two hardcoded name lists had to
agree and did not. The grouping is now derived from the generated set and
asserts that nothing goes unwritten, and a test holds the round trip the file's
own header promises. No colormap data changed.
