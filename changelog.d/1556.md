#### An integer `--seeds` is a whole-volume budget a tiled fit divides

A default `luxar gsplat cal` reports a whole-volume K*, and the documented
pipeline is `cal` → `fit --seeds K*`. But when tiling engaged — `--tiling auto`
on a large stack, an explicit `--tiling uniform`, a `--tile k/M` worker, or a
uniform-mode `batch-fit` task — the same `--seeds K` was handed to *every* tile,
so the realized total was roughly K × n_tiles. A 108×1352×532 stack fitted with
`--seeds 256000` auto-tiled into 21 tiles and produced 2,449,962 splats in
17.4 min instead of ~256,000 in 1.9 min, with nothing to warn that the number
asked for was not the number being fitted.

An integer `--seeds K` is now read as a whole-volume budget: a fit split into N
tiles seeds each tile with `ceil(K / N)` — divided across the tiles instead of
multiplied by them — and prints the budget, the per-tile count and the tile
count as it does so. That notice is emitted wherever the tile count is first
known, so it survives the paths that capture worker output: the parent of a
parallel `-j` run prints it, and `batch-fit run` / `submit` print it at plan time
(visible under `--dry-run`). It is a budget, not an exact count: tiles that
window to near-zero signal are skipped entirely, so a sparse volume realizes
less than K, and a K smaller than the tile count gives one seed per tile. A
non-positive `--seeds` is left untouched so the fitter still rejects it, as it
does on the whole-volume path.

The division happens once, in the single-tile worker and the in-process
sequential tiled path, so a parallel `-j` run (whose workers each re-enter
`fit --tile i/M`) and a `batch-fit` task (likewise a `--tile k/M` invocation, per
(t, c) volume) inherit it without double-dividing. A *ratio* `--seeds` (a float
in `(0, 1]`) is left untouched: a ratio is a fraction of whatever voxels it is
applied to, so it already means the same density per tile as whole-volume.
`--tiling content` is unaffected — it already ignores `--seeds` and sizes its
boxes from the density plan. The library entry points `fit_tiled` / `fit_tile`
keep their per-tile `seeds` semantics, now documented as such.

One caveat comes with it: `cal --auto-region` calibrates on a content-rich
sub-volume, so *its* K* is region-scoped rather than whole-volume and does not
belong on `--seeds`. `cal` now says so where it matters — the
`★ Recommended K*` headline is marked region-scoped whenever a real crop was
used, pointing at `fit --tiling content --cal` (the `splat_density` transfer)
instead of `--seeds`. A volume small enough that the region short-circuits to
the whole array is correctly left unflagged. The tutorial documents both, plus
the rough uniform-tiling alternative of scaling a region-scoped K* by the tile
count.
