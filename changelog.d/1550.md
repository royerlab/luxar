#### An invalid `partition=` spec on the gsplats wrapper doors no longer strands a wrapper

`add_gsplats_from_data(..., lod_group=True, partition="nonsense")` raised
`Could not add gsplats 'child_0': partition must be None, True, or dict; got
str` and left `g` on disk as a childless `kind=lod` group that survived
`finalize()` — so it reached the viewer. The same held for `partition=3`,
`partition={"max_elements": 0}` and `partition={"rule": "bogus"}`: the two
faults #1529/#1534 closed elsewhere, a stranded wrapper and a message blaming
an internal `child_0` for the caller's own kwarg.

#1534 hoisted `validate_render_attrs` into the pre-wrapper gate on this door,
which closed the bad-attr-KEY half. The spec half stayed open because
`partition` is one of the three keys that gate deliberately excludes — it is a
named parameter of the leaf adder and must ride through to drive each child's
BSP split — so its VALUE was still judged one level down, inside `child_0`,
after `add_lod_group` had created the group. The fix is not a wider exclusion:
excluding the key is exactly what lets a valid spec through.

The leaf adders' partition-spec validation is now one function,
`core/group/partition.py::resolve_partition_spec`, replacing four byte-identical
inline copies (Points, Lines, GSplats, and Mesh's private
`_resolve_mesh_partition`). The gsplats `lod_group=` gate calls it in the slot
right after the node-attrs gate, for its verdict alone. Messages and exception
types are unchanged and now byte-identical to the flat `add_gsplats(...,
partition=<same bad value>)` call, prefix included, with nothing written on a
refusal. Precedence parity with the flat path is pinned in both directions now
— the node-attrs gate above the check still wins, the labels refusal below it
still loses — because the slot, not the check, is the design claim here.

The GRAFT door had the identical bug and is closed the same way.
`scene.add_gsplats_from_file("g", <nested .gsplats.zarr>, partition="nonsense")`
answered `Could not add gsplats 'part_0': …` and left the `kind=partition`
wrapper on disk through `finalize()`, because `graft_gsplat_node` builds its
wrapper from the stored tree before the first leaf write; one call in the slot
that already holds that door's `strip_absent_attr_kwargs` /
`reject_data_owned_channels` pair fixes it, with the same message parity.

Two values are deliberately NOT judged, at either door, because the leaf does
not judge them either. `partition=False` is vocabulary, not a bad spec — it is
the explicit no-partition bypass, and the only way to opt a `lod_group=` ladder
out of a compiler-level `auto_partition_max_elements` (which would drop
`coverage_fraction` and break the LOD selector). And below 2 spatial dimensions
the leaf DROPS the request with a warning before it ever resolves the spec, so a
1-dimension scene accepts even a nonsense spec on the flat path; the gates skip
silently there rather than emit a second warning.

One VALID-spec strand of the same shape is closed alongside it:
`add_gsplats_from_data(..., additive_lod={…}, partition={"max_elements": 2})`
answered `Could not add gsplats 'child_0': Unknown node attribute 'partition'`
and stranded the `kind=lod` wrapper, because the multi-LOD child writer has no
`partition` parameter. It is now refused up front, above the route branch so
both routes say the same thing: partitioning a ladder is a feature, not a
wording fix. Known and NOT closed here: `partition=False` on that same
`additive_lod=` route still reaches the child writer as an unknown node
attribute — a surviving twin of the `partition=None` case #1496 fixed by
treating an explicit `None` as absent, and a design call (drop the key, or teach
the writer to ignore it) rather than part of this gate.

The sibling `substitutive_lod=` doors on Points, Lines and Mesh were checked
for the same shape and do not have it: all three refuse `partition=` together
with `substitutive_lod=` outright ("partition-of-substitutive is not
implemented"), before any wrapper exists, so an invalid spec can never be
forwarded into a ladder child there. That survey covered the gsplats
`lod_group=`/graft doors and those three; it is not a claim about every adder
kwarg that rides into a child.
