#### L2 write queue keeps a bound without throwing away the cache

The viewer's background OPFS write queue capped the bytes its pending writes retain at the larger of the resolved L1 budget and 64MB. That charged the queue for memory it does not own: a pending write holds the very same buffer the L1 entry holds, so while the entry is L1-resident it costs one extra reference rather than a second copy, and the only genuinely extra retention is the set of writes whose L1 entry has since been evicted. On a machine whose L1 resolves to around 100MB the cap therefore bound at roughly half of what a large scene streams, and the L2 tier silently went back to dropping most of its writes — a second visit re-fetched nearly the whole store.

The allowance is now derived from the heap headroom left outside the cache pool, the same model the eager loader's working-set budget uses: a quarter of that remainder, capped at 512MB, and 256MB where no memory signal exists at all. On a 4GB Chrome heap that resolves to 328MB, which clears both the 214MB peak measured on the largest audited scene and that scene's 277MB whole-store ceiling — by 1.18× on the latter, so the margin is real but not large. The allowance is heap-relative by design: below roughly a 2.7GB heap it binds again for that scene and writes are dropped, which is the correct behaviour when the memory to retain them is not there. The eager working set takes half of the same remainder and the last quarter is claimed by neither. Overflow also drops the arriving write instead of the oldest pending one — the queue drains from the oldest end, so evicting there kept discarding the write that was about to run and left a scattered remnant on disk, whereas dropping the arrival lets that end drain in order and leaves contiguous runs a warm revisit can serve from, at no more drops than before. The opt-in performance bench now asserts the drop counter is zero — at the end of every cold repetition as well as during the load, and on the warm revisit — whenever the resolved allowance covers the bytes the scene streamed, and records that allowance in its result row, so a cap that binds again is visible as a bench failure instead of only as a slower second visit.
