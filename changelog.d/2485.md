#### Slice-even additive ordering for gsplat nodes the viewer slices

A gsplat node with a hidden dimension is shown one coordinate at a time, but an
additive rung is sized against the whole node — and because a rung is a global
contribution-ordered prefix, it does not divide evenly either: it piles onto
whichever coordinates carry the signal. The NEXRAD supercell demo authored an
absolute `breakpoints="stream:20000"` first rung over 82 radar scans and 817,989
splats; where that spec actually computed, its 5th-percentile scan held 4 splats,
which `scripts/check_demo_ladders.py` fails on both its absolute first-paint
floor and its rung-0 share floor.

`make_additive_lod` and `compute_additive_order` now take `slice_dims=`, a list
of centre columns whose distinct combinations the viewer slices. The ordering
chosen by `method=` is re-emitted round-robin across those slices, so after `R`
passes every prefix holds `min(slice size, R)` elements of each slice: an equal
*absolute* budget per slice, with any slice smaller than the budget carried
whole. It is a modifier rather than a new ordering method — it composes with all
of them, and the order *within* a slice stays whatever the method produced, so
each coordinate still paints bright-core-first rather than evenly thin. It is
also deterministic, which sizing alone is not: that stack's sparsest scans hold
562-774 splats, so the 250-element floor needs about a third of the sparsest one,
and a uniform random permutation is proportional only in expectation — over seeds
0-7 an `n_lods=3` random ladder cleared the floor five times in eight.

One trap surfaced on the way, worth knowing if you author a stacked gsplat
scene: an `additive_lod=` spec is silently a **no-op** on a dataset built with
`GSplatData.combine_as_new_dimension` from sources that already carry ladders.
The combine *merges* those ladders rather than dropping them — rung *i* of every
source becomes rung *i* of the stack — so the result arrives with rungs to spare
and `resolve_additive_axis_gsplats` takes its pass-through branch, which computes
only when the level holds one rung or `recompute=True` is set. What survives is a
per-source equal-count ladder, which is exactly proportional per slice and so
starves a sparse slice just as a global prefix does. Pass `recompute=True`
alongside `slice_dims=`; the store's tell for the shadowed case is an
`additive_0/lod_stats` carrying `n_sources` and no `lod_method`.

The NEXRAD demo now authors
`additive_lod=dict(n_lods=4, slice_dims=[3], recompute=True)`, whose rung 0
budgets roughly 2,494 splats per scan and therefore carries the 5th-percentile
scan complete at 774; without the flag the merged per-frame ladder left it at
774/4 = 194, still under the floor. The demo authoring gate grew a sibling that
walks the gsplats adders too: the older check only read `add_points` and
`add_lines`, which is why an absolute first rung on a sliced gsplat node was
invisible to it.
