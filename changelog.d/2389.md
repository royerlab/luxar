#### The sliced-ladder gate now measures the sparsest slice, not the busiest (#2389)

`check_demo_ladders` gained a sliced-node arm in #2380: a node the viewer slices
fails when its rung-0 first paint is too thin, because playback commits rung 0
and re-pays it every tick. It reduced the per-coordinate histogram with `max()`,
which asks whether the node's **busiest** slice is healthy — so a node with one
fat coordinate passed however many starved ones sat beside it.

That is not hypothetical. Measured on the built demos, the spread between the
5th percentile and the maximum runs from 2.1x (`celegans_tracking`) to 122x
(`nexrad_supercell`), and `zebrafish_timelapse/endoderm` passes the old
reduction on a maximum of 6,648 while a twentieth of its timepoints hold 330
elements or fewer at rung 0. A ladder starves at its sparsest slice, so the
reduction is now the lower 5th-percentile order statistic — an actually observed
count, never an interpolation, so the number in a failure message names a slice
that exists. At twenty or fewer coordinates it is simply the minimum.

The absolute floor moves 2,000 -> 250 as a consequence, because the two changes
are coupled: a percentile sits far below a maximum, and at 2,000 both
`zebrafish` and `celegans` would fail despite playing acceptably. The new value
is calibrated against what the deployed viewer actually commits while the axis
plays, rather than chosen — the boundary between "structure gone" (nexrad, p05 =
4, renders 187-440 of ~10,000) and "soft but usable" (zebrafish, p05 = 330,
renders ~1,449 of ~11,159) lies between 4 and 330, and 250 sits in that gap with
the closest passing store clearing it by 32%. Every verdict on the five measured
sliced demos is unchanged; only the false negative closes.

A second, independent arm fails when rung 0 is not a usable **share** of the
node (default 10%). Five stores built before that contract sit at exactly 6.25%
— a 16-rung ladder — and their rebuild was *cancelled* rather than postponed,
because measurement showed their axes are keypress-navigated: that takes the
loader's `refine` pass rather than the budgeted `playback` one, so they stream
past rung 0 and converge instead of starving a frame. They are therefore carried
as a **shrinking allowlist keyed to that reason**, not as a warning. A warning
would never clear — nothing is scheduled to rebuild them — and an arm that
warns forever has stopped being a gate; as an allowlist it still bites on
anything new, each entry states the measurement that justifies it, and the list
empties if those stores are ever rebuilt. Each entry is also bounded at 6%, just
below its measured 6.25%, so a degraded rebuild goes red instead of inheriting a
stale path exemption. Tests pin both the exempt and failing paths, so an entry
cannot quietly disable the arm. A whole-corpus sweep before the paired
share-accounting correction found the failure count unchanged at 250, with the
five exemptions reported as warnings; the corrected accounting was not
re-swept in this checkout. The share denominator adds only attr reads to the
existing histogram pass, and it is the gate form of the authoring contract
added in #2384. The absolute arm catches a
node whose share looks healthy because the node is small; the share arm catches
a ladder that is simply too deep, which is the #2376 shape. Neither subsumes the
other. Sliced-arm failure messages also report how many coordinates rung 0
covers, so a node whose rung 0 misses coordinates the node itself spans is at
least legible when another arm fails — those coordinates cannot lower a
percentile computed only over rung 0.
