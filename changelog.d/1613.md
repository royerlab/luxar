#### Scene metadata authored through `scene.attrs` now reaches the store

`Node.attrs` handed back the in-memory cache dict, so `scene.attrs["title"] = ...`
mutated a dict and nothing else. 38 demo modules author scene provenance that way
— 36 set a `title`, 23 a `description` — and none of it was on disk afterwards.
Nothing reads a root `description` today, so no output was visibly wrong; the cost
was 38 files carrying code that reads as publishing per-scene provenance and
doesn't, plus the trap waiting for whoever added the first reader.

`attrs` is now a write-through mapping. Assignment, deletion and the standard
mutable-mapping helpers (`update`, `pop`, `setdefault`, ...) all take the
persistence path the node property setters already used, so a mutation made while
the `LuxarZarrCompiler` is open lands in the group's attributes. Recognized render
attributes are routed through their validating property setters first, so
`node.attrs["transform"] = matrix` gets the same column-major normalization — and
the same guards — as `node.transform = matrix`, and a lines-only `join` on a
points node is still refused. Cache and store move together: a value the writer
rejects changes neither. Mutating after the writer has been finalized still
updates only the cache, and still warns.

Two smaller consequences. `Scene.viewer_config = None` now removes the stored
attribute instead of only forgetting it in memory. And `GroupAttrs` is
`MutableMapping[str, Any]` rather than `Dict[str, Any]`; the returned view keeps a
`copy()` for parity with the dict it replaced, and `dict(node.attrs)` gives a
detached plain dict for anything else.
