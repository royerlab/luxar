#### Failed gsplat file grafts no longer leave empty wrappers

Grafting a nested `.gsplats.zarr` into a scene is now transactional. If a child
write fails after the graft has created its `kind=partition` or `kind=lod`
wrapper, Luxar removes the whole new subtree from both the Zarr store and the
in-memory scene graph, and restores compiler-side bounds and warning claims
before re-raising the original validation error. This covers valid
energy-fraction `additive_lod=` conflicts as well as malformed specifications,
while preserving any node and bounds that existed before the graft began.
