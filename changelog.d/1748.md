#### A stacked time or channel axis survives quantization again

`combine_as_new_dimension(sigma=0.0)` is the documented way to stack per-timepoint
fits into a 4D dataset — the docstring recommends `sigma=0.0` for "discrete
dimensions (e.g., time frames)". It gives the new axis an effective sigma of
1e-7, the epsilon `trils.py` substitutes so the covariance stays
positive-definite.

Saving that dataset then destroyed the axis. Centers are stored as per-axis
uint16 fixed-point, so each value moves by up to half a quantization step; on a
100-frame stack that is 7.3e-4, or **7 320 σ**. Interior frames landed far enough
from where they belonged to stop matching a slice query at all, so they simply
did not render. Only the two range endpoints survived — 200 of 5 000 splats —
which is the worst possible symptom, because the first and last frame of a
timelapse look perfect while 96 of 100 are gone.

Two things made this hard to notice. It was **not** opt-in: `AUTO`, the default,
behaves identically to `MEMORY`, so any stacked dataset saved with default
settings was affected, not just the demos that named a lossy mode. And it is
**not** a large-N problem: the sigma is a fixed constant while the quantization
step scales with the axis, so even a three-frame stack puts the middle frame
153 σ off.

The encoder now **snaps a gridded axis's quantization grid onto the data's own
spacing** — for an axis whose values are evenly spaced, `hi` is
widened to `lo + step·65535` so the stored grid coincides with the values and
they round-trip exactly. A 100-frame stack goes from 7 320 σ of error and
200/5 000 exact splats to **zero error and 5 000/5 000**, under `AUTO`, `MEMORY`
and `PRECISION` alike.

This costs nothing. `lo`/`hi` are already stored per axis, so it is a scale
choice rather than a dtype change: the store stays 3.01 MB and the decoder and
format are untouched. The obvious alternative — falling back to float32 — is also
exact but converts *every* centers axis, since centers are one array with one
encoding; measured at +78% on the same store (+123% for whole-store `PRECISION`).
No demo needs to change its encoding mode.

Ordinary data is left exactly as it was: continuous coordinates, irregularly
spaced values, constant (zero-extent) axes, and axes with more distinct values
than the encoding has levels (nothing to snap to) are all untouched. That selectivity matters because this code path
encodes positions, line vertices, mesh vertices and splat centers alike.

The snap reports through arbol rather than `warnings.warn`. A warning means the
caller should act; this is a transparent correctness fix with nothing to do, and
warning would fire on every stacked scene.
