#### Per-shard depth bounds from the sort kernel

The depth-sort kernel can now report, for each of `N` contiguous equal-population
ranges of the ordering it produces, the local-space bounding box of the elements
that range draws. Since the permutation is already back-to-front, a contiguous
range of it is a depth interval — which is the groundwork for compositing two
overlapping order-dependent nodes correctly against each other instead of
drawing one entirely before the other
(`docs/guides/specs/CROSS_NODE_DEPTH_ORDERING_SPEC.md`).

Nothing requests these bounds yet, so there is no behaviour change and no cost:
a shard count of zero skips the pass and leaves the outputs untouched, which is
every node today.

Two details that shaped the design. The kernel returns boxes rather than
centres and radii because `min`/`max` over floats involve no rounding at all, so
the WebAssembly kernel and its TypeScript twin agree bit-for-bit without any of
the careful operation-order mirroring the depth-key maths needs. And a `NaN`
coordinate is excluded from its box rather than poisoning it, so one bad element
among thousands cannot cost a whole range its place in the eventual ordering;
`±Infinity`, which does compare meaningfully, still propagates out to the
caller's non-finite guard.
