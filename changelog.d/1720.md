#### The content hash now covers overlay image bytes

An overlay image lives inside its zarr group as a plain file, named by the
group's `image_file` attr (`overlays/<name>/image.png`), with no chunk grid and
no zarr metadata. The finalize-time hash walk enumerated `array_keys()` and
`group_keys()`, so it never saw those bytes: two scenes compiled from the same
script and differing *only* in their overlay image received the same root
`content_hash`. That token is advertised as a content fingerprint and consumed as
one — the viewer's scene-identity watchdog, cache validation — so a rebuild whose
only change was the logo was indistinguishable from no rebuild at all. (zarr had
been telling us all along, in its own way — every compile with an image overlay
warned that `image.png` "is not recognized as a component of a Zarr hierarchy".)

`compute_content_hashes` now folds such payload files into each group's digest,
between the attrs and the child groups, reading them through the store itself via
a new `_zarr_compat.read_raw_bytes`. Which attrs name a payload is a list
(`PAYLOAD_FILE_ATTRS`, today just `image_file`); a payload that cannot be read
folds a deterministic sentinel rather than failing the compile, and the three
ways that can happen — missing, refused by name, refused by the store — stay
distinguishable from each other and from a zero-byte file.

A group naming no payload file adds no terms at all, so a payload-free store's
digest is byte-identical to what previous versions produced and existing caches
are not invalidated wholesale. For a scene that *does* carry an image overlay the
consequence is the intended one: a rebuild changing only the overlay image moves
the root hash, so a client holding that dataset in its L2/OPFS cache re-downloads
its chunks once — which is exactly what the token exists for. Scope note: this is
a compile-time fingerprint, so replacing the PNG inside an already-finalized
`.luxar.zarr` restamps nothing. The metadata-only `_stamp_content_hash` used for
`.gsplats.zarr` is deliberately untouched: those stores carry no overlays and
that variant must never read bytes.
