#### Invalid `extend_to_all` no longer strands wrapper groups

An invalid explicit `extend_to_all` value is now checked before Points, Lines,
or GSplats creates a `kind=partition` / `kind=lod` wrapper, alongside Mesh's
existing preflight. The refusal therefore leaves both the Zarr store and scene
graph untouched instead of stranding a childless wrapper when the first
generated child validates the value.

The shared preflight runs only when a wrapper will actually be written and
keeps each door's kwarg-spec, image-label, and topology checks ahead of it. It
now precedes pre-split channel validation, matching the flat writer's order.
`extend_to_all=None` remains a per-child check, preserving the advisory
candidate warning once per written leaf rather than adding a warning for the
unsplit source array.
