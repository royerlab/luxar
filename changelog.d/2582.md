#### Viewer: shared input-capabilities profile, with iPhone and iPad recognised explicitly

The viewer now derives one memoised input profile (`utils/input-capabilities`)
that every touch adaptation reads: whether the primary pointer is coarse,
whether any pointer can hover, the touch-point count, the device class used for
memory budgets, and explicit iPhone / iPad / Android flags. iPadOS Safari
reports a Macintosh user agent by default; the profile unmasks it from a `Mac`
platform combined with a multi-touch screen, and an iPad with a trackpad keeps
its hover affordances while a bare iPad does not. The cache-pool device class
now comes from the same profile. A JS-only `?input=touch|mouse` URL parameter
forces the profile for testing and support. This is the foundation for the
touch-navigation, tap-to-pick, coarse-pointer layout and mobile-budget changes
that follow; on a mouse-and-keyboard machine nothing changes.
