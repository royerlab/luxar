#### A content-planned fit keeps the truncation radius it was fitted with

`gsplat fit --tiling content` stored the wrong support for its own splats. With
`truncate: 3.5` in a `--config`, a uniform tiled fit of the same volume and the
same config recorded `truncation_radius: 3.5`, while every box of the content fit
recorded the 2.75 default — the fit ran at 3.5 and the store then claimed 2.75,
so the renderer evaluates each Gaussian over a smaller support than it was
optimised for. `--plan-box K` (which is also what every array task of a content
`batch-fit run`/`submit` invokes), the sequential boxes and the `-j N` parallel
merge were all affected; a partition and a `--flat` leaf alike.

The user-visible consequence was worse than a wrong attribute, because
`GSplatData.concatenate` **requires** its inputs to agree on the radius: a
content result no longer composed with a uniform-tiled one produced from the same
config, failing with "Truncation radius mismatch". Merging a content fit of one
channel with a uniform fit of another was simply impossible.

The cause was a lossy internal hand-off. The per-box fitter returned bare
`(centers, amplitudes, cholesky_factors)` arrays, so all four consumers rebuilt a
`GSplatData` from those three arrays alone — and a rebuilt dataset takes the
default radius. It now returns the fitted dataset itself, and the two flat merges
go through `GSplatData.concatenate` (what the uniform tiled path already used),
which carries the shared radius through. A box with a zero budget fits nothing but
still answers with the radius its config asked for rather than the default.

The `-j N` path had a second, independent copy of the same bug: the box workers
were handed only `--preset`, and `truncate:` is settable *only* through a YAML
`--config` (no preset sets it, and there is no `--truncate` flag), so every box of
a parallel run fitted and stamped the default no matter what the config said. The
`--preset` they were handed made it worse: an absent `--preset` was substituted
with `standard`, whose 5000 iterations and `cull_retention: 0.999` a sequential
`-j 1` run never applies (it resolves 1000 / 0.95), so `-j N` fitted with different
parameters than `-j 1` even without a config. The run's fit configuration
(`--preset`, `--config`, `--iters`, `--loss`, `--lr`, `--cull-retention`) is now
forwarded verbatim to each box worker — an absent flag stays absent — mirroring the
uniform-tiled sibling, so both paths resolve the same fit config. `--seeds` is
deliberately not forwarded: a content box's budget comes from the plan.

Per-box fit stats (`psnr_db`, `final_loss`, `iterations`, the normalization
metadata) ride along with the radius, reaching each part of a bare-leaf
`kind=partition` result instead of being dropped at the box boundary. (With
`--recipe stream|levels` the ladder builder writes its own per-sub-LOD stats, and
on `--flat` `concatenate` replaces them with its merge summary, so the per-box
values are visible only on a bare-leaf partition.) Part of the set is re-scoped to
what the part actually holds: a box is fitted on a halo-padded crop and then
core-masked, so the crop's region stamps — the whole `source_shape` /
`source_voxels` / `source_bytes` / `fitted_shape` / `fitted_voxels` / `occupancy` /
`voxels_per_splat` group a `--bbox` crop already drops — go whenever the padded
crop is larger than the box or the mask removed splats, and `n_splats` is
restamped to the kept count. The remaining figures (`psnr_db` / `ssim` / `mse`,
the `final_*` losses, the cull provenance `n_original` / `n_culled` /
`amplitude_retention`) are the box's own fit provenance — measured on the padded
crop with the pre-mask splat set, the same provenance a uniform tile-part carries
— not part-scoped fidelity. A non-finite figure is dropped rather than persisted:
a signal-free crop fits to `psnr_db = inf`, the leaf writer stamps `lod_stats`
raw, and zarr would emit a bare `Infinity` token that a strict JSON parser (the
viewer's) refuses. The flat merged leaf's
stats keep every `planned_fit` / `n_boxes` / `n_boxes_fit` / `overlap` /
`volume_shape` key it had before, now beside `concatenate`'s own
`concatenated_from` / `splats_per_source` summary — with `time_seconds`
overwritten by true wall clock, as the uniform tiled merge already does.

One caveat for a content `batch-fit` run that is already in flight: its finished
tiles carry the old radius, and a resume only fits the missing ones. Mixed radii
either stop the merge (`concatenate` refuses them when it stacks a spatial slot
across timepoints or channels) or, for a single-`(t, c)` streaming merge, pass
silently with each part rendering at its own support. Re-fit the tiles of such a
run — `batch-fit validate` checks store integrity, not the stamped radius.
