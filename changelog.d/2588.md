#### Viewer: phones and tablets get device-aware rendering and memory budgets

On a phone or tablet the viewer used to start at desktop settings and then
struggle: a scene authored for high-DPR rendering opened at the panel's full
pixel ratio (nine times the fragment work of CSS resolution on a DPR-3 phone),
the GPU geometry budget fell back to a 512 MB desktop default because WebKit
exposes no memory signal, a single node could allocate a gigabyte-scale element
texture, the adaptive-resolution floor dropped to a sixth of the panel's linear
resolution, and a 120 Hz iPad's learned refresh rate made a steady 60 fps look
like distress. The runtime now recognises the mobile device class: "allow high
DPR" caps at 2 (explicit pins are untouched), the adaptive floor is 0.75 with
thresholds capped at 60 Hz, the GPU byte budget takes the mobile cache pool's
share (128 MiB) as a peer minimum, per-node element textures are bounded to
256 MiB, the data-worker pool is capped at three, and the blend-variant shader
warm-up is skipped. Laptops and desktops resolve every one of these exactly as
before.
