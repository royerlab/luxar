#### The writer protocol now type-checks the compiler that implements it

`ZarrWriterProtocol` declares the contract every Zarr writer must satisfy, and
its one implementation had opted out of it: all four geometry write methods on
`LuxarZarrCompiler` carried `# type: ignore[override]`, so nothing verified the
417-line interface against the code behind it.

Two disagreements were hiding there. `io/writer.py` defined its own
`PositionArray` and `ColorArray` — wider than the same names in
`typing_utils.aliases`, in a module that also imports from it — so the protocol
and the compiler were annotated from two different vocabularies and could not
agree. Writing a store per candidate dtype settled which was right: the write
path really does accept float16 positions, uint8 and uint16 colors, and
float16/uint8 scalar attributes, so the narrow annotations were the fiction.
There is now one definition of each, threaded from the public method down
through the geometry writers, spatial ordering, dataset writers and validators.

The second was a plain bug. The protocol's `write_mesh` omitted the eleven
texture parameters the compiler takes between `scalars` and `shading`. Those are
positional-or-keyword, so their absence renumbered every argument after them: a
caller typed against the protocol and passing `shading` positionally would have
set `uvs` instead.

Nothing about how data is written changed — these are annotations. What changed
is that mypy now checks all four methods, and a new test pins the parameter
names, order and defaults of all sixteen declared methods, plus the input dtypes
the aliases promise.
