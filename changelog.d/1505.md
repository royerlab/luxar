#### The one-flat-leaf graft exemption now checks LENGTH, not just shape (#1505)

`#1471` exempted exactly one shape from the graft door's labels gate
(`_reject_labels_on_a_grafted_wrapper`): a grafted subtree that resolves to a
single leaf with a single additive sub-LOD, because that leaf holds every
splat and so has an exact per-element correspondence for `labels` /
`image_labels`. What it did not check on that exempt branch was whether the
list was the right LENGTH for that leaf. Measured on `main`: grafting a
5-splat leaf under a one-part `kind=partition` with an 8-long `labels` sailed
straight through the exemption and refused one level down instead, from
inside `part_0`'s own leaf write — `Could not add gsplats 'part_0': labels:
Labels length (8) must match element count (5)` — with the childless
`kind=partition` named by the caller already on disk, surviving `finalize()`.
`image_labels` stranded identically (`Image labels length (8) must match
element count (5)`), and the flat control — the same three arrays via
`scene.add_gsplats(...)` — refused with the byte-identical message and wrote
nothing at all.

The exempt branch now validates whichever channel(s) are present, in the flat
writer's own order (`labels` then `image_labels`, `write_gsplats` steps 0d
then 0e), reusing the same validators the flat writer runs rather than
reimplementing either rule:
`core.group.compositing.validate_labels_before_split` for `labels`, and
`io._compiler.labels.image_labels.validate_image_labels_for_writing` for
`image_labels` (guarded on `is not None`, since that validator has no
built-in no-op). Both are caught as `(ValueError, TypeError)` and re-raised
with the same hand-applied `Could not add gsplats '<name>': ` prefix the
gate's other refusals already use, `from e` — `TypeError` matters here too,
since some malformed `image_labels` inputs (a non-integer dict key, a
one-shot iterable, a wrongly-typed entry) raise that rather than
`ValueError`, and the leaf adders' own `except (ValueError,
TypeError)` funnel converts it on the flat path, so skipping it here would
have made the two paths diverge in exception TYPE as well as message. The
leaf's own `n_splats` is unambiguous at this call site: `GSplatLeaf.n_splats`
sums over every additive sub-LOD, but the exempt branch is only ever reached
after the caller has already ruled out more than one, so the sum degenerates
to that one sub-LOD's own count.

Placement matters: the length check lives strictly below the multi-leaf and
laddered-leaf refusals, so a wrong-length channel on a shape that is ALSO
structurally disqualified (a multi-leaf graft, or a one-part partition of a
LADDERED leaf) still gets that shape's own structural message, not a length
one — those faults keep precedence, as everywhere else in this gate.

The verdict is now byte-identical to the flattened control's, both channels,
on every one-leaf shape the exemption covers — a direct one-part
`kind=partition`, a bare-leaf graft, and a nest that still resolves to a
single leaf two wrappers deep — for a single-fault call. The new check is the
first statement of `graft_gsplat_node`, so a call that ALSO trips an unrelated
fault (an unknown attr, a bad node name, a duplicate sibling name, NaN
centers) now hears the label fault here, where the flat path answers the
other fault first; both refuse and neither writes. That is not a new problem:
it is the same documented trade
`compositing.validate_points_channels_before_split` already names for "a NaN
position, an unknown attr", and `from_data._reject_before_wrapper` already
makes it on the `lod_group=` door, so the placement is unchanged — only this
note is new.
