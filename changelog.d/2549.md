#### Luxar's console output can now be turned down, or off

Everything below the CLI narrates through arbol — 547 `aprint` calls across
`gsplats`, `io` and `core` — which is the right default for a long CLI run and
the wrong one in a notebook cell or a napari plugin. There was no way to say so:
no `verbose` or `quiet` parameter on `Scene.save()` or `fit_gaussian_splats()`,
and no switch that was part of Luxar's own API.

```python
import luxar

luxar.set_verbosity("silent")     # process-wide: silent | summary | normal | full
with luxar.verbosity("summary"):  # scoped, restores on exit
    scene.save()
```

`"full"` remains the default, so nothing changes for code that does not call
this. An integer sets an explicit tree depth. Note that `0` is *not* silence —
arbol at depth 0 still prints top-level lines plus a truncation notice for each
section it truncates at the cap — so pass `"silent"`; a bool is refused outright
because `set_verbosity(False)` reads as quiet but would resolve to that
non-silent depth 0.

Warnings routed through `arbol_warnings()` now fall back to Python's standard
stderr display whenever arbol output is disabled or the current section is
below its depth cap, instead of being dropped. This also applies to existing
callers that set a finite `Arbol.max_depth` without using the new verbosity API.

The setting drives arbol's own switches, which are class attributes, so it is
process-global rather than per-call and is not thread-safe. Both constraints are
documented on the module. A per-call argument and a `logging` bridge remain
possible later; neither is needed to make the output silenceable.
