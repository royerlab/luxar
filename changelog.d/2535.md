#### Six fit parameters had drifted to different defaults in different places

The Gaussian-splat fit schema is restated along its call chain, and nothing checked that
the restatements agreed. `prepare_fit_config` — public API — disagreed with
`fit_gaussian_splats` on five defaults, and a `FitConfig(...)` that supplied its required
fields while omitting `max_eccentricity` disagreed on a sixth: it left the limit unset,
while every documented default said 10.

All six now match the documented entry point. No internal path was affected —
`fit_gaussian_splats` passes those parameters explicitly — so the divergence only ever
reached callers who used the lower-level functions directly, which is why it went
unnoticed.

A new schema-agreement test derives both sides and fails on any shared parameter whose
default differs, so adding a knob in one place and not another goes red. It also pins
the published contract for `OptimConfig`/`LossConfig`/`ConstraintConfig`: unpacking a
default bundle into `fit_gaussian_splats` must change nothing.
