#### `gsplat lod` keeps the appearance you authored

A recipe rebuild owns the *structure*, not the look. It was silently dropping
both: the builders construct fresh nodes that know nothing about the input, so
the writer's own defaults took over — `blending_mode` disappeared entirely and
`opacity` / `gamma` / `intensity` / `absorption` snapped back to their identity
values. Tune a dataset in the Layers panel, re-ladder it, and every one of those
choices was gone, with a result that still looked structurally perfect.

The source root's compositing attrs now travel to the output root through the
writer's lowest-precedence channel, so the rebuild's own structural attrs still
win. Both write paths carry them — the matrix recipes (`stream`, `levels`) and
the composed ones (`tiles`, `overview`, `adaptive`).

`colormap` and the amplitude/scalar display window are deliberately *not*
carried: the writer auto-defaults them per group, which sits nearer the leaf than
the root and would shadow a carried value — preserved on disk, ignored on screen.
Carrying those needs the writer to stop defaulting when an ancestor authored one,
tracked with the rest of the sweep in
[#1600](https://github.com/royerlab/luxar/issues/1600), which asks that every
command rewriting a dataset be idempotent for what it does not own.
