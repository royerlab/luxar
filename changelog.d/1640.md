#### The E2E render waits stop hanging on a starved page

Tests in `webgl-errors.spec.ts` started failing on a Linux/NVIDIA workstation
without catching anything: they died on `Test timeout exceeded` while still
waiting for frames, having seen no `GL_INVALID*` and no "Vertex buffer is not
big enough" at all. The cause is in the shared helper. `page.evaluate` is
dispatched with no timeout of its own — neither `actionTimeout` nor
`setDefaultTimeout` bounds it, only the test budget does — and the frame-counter
read and the `renderOnce()` kick in `waitForNextRender` were both unbounded
evaluates. Every other wait in that helper is capped and swallowed, so on a page
too starved to answer (the app drops from ~30 FPS to ~4 under load here) the
helper blew past its own fallback instead of taking it. Both evaluates are now
raced against `Math.min(timeout, 3000)`: an unanswered read yields `null`, which
already routes to the state-based fallback, and the kick is best-effort.
`waitForRenderStable` carried the same two unbounded evaluates verbatim and gets
the same treatment, so the fix reaches all thirty-five specs that pace
themselves on a render. Falling back promptly is not the same as having
rendered, though, so `waitForNextRender` now warns once naming which branch it
took and returns `false` instead of reporting nothing; all 263 existing call
sites ignore the return value and are unaffected.

The spec file also opts back out of `fullyParallel` with
`test.describe.configure({ mode: 'default', timeout: 120000 })`. It is
resource-bound — ten tests performing ~14 scene loads over one dataset server,
OPFS and the GPU — and it used to run sequentially against a two-worker pool, so
the ambient load from three other workers is worse than what this restores; the
raised budget is headroom on a loaded machine, not the cure. `default` rather
than `serial` keeps all ten detectors reporting. Finally, a file-level
`afterEach` prints whether any WebGL-error text was observed whenever a test
ends unexpectedly (skips excluded, since a skipped test observed nothing by
construction), because a timed-out test never reaches its own `expect` or its
dumps and the shared fixture skips teardown for `timedOut`.
