#### Depth sorting on the GPU for native WebGPU (opt-in)

Order-dependent blending (normal, volumetric) draws points, lines and splats back to front. On WebGPU the CPU sort worker's order was uploaded whole on every re-sort, 40 MB for a 10M-splat node, and that upload, not the shaders, made large sorted scenes slower than on WebGL: on an RTX 3070 a 10M-splat orbit's frame p95 was about twice WebGL's.

On a native WebGPU device the viewer can now sort these nodes on the GPU instead. A compute pass reads each element's center from the element texture already on the GPU and writes the order into the buffer the vertex shader reads, so a re-sort moves nothing across the CPU. A 10M-element sort takes about 9 ms of GPU time on an RTX 3070. The order matches the worker's to within one depth bucket for a rare element near a bucket edge. Mesh nodes, nodes too large for the device, and the other backends keep the worker, and so does everything while the pipelines compile or after a device loss.

It is off by default for now (`config.depthSort.gpuSort`); `?gpuSort=1` turns it on and `?gpuSort=0` off. `__luxarDebug.readDrawnOrdering(uuid, count)` reads back the order a node is drawn with.
