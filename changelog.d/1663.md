#### A demo's LOD topology is now chosen, not inherited from its fitter

Whether a cached demo artifact shipped a streaming ladder used to depend on
which fitter the demo called. `GSplatData` carries `additive_sublods`, the
progressive fitter returns several as a by-product of its passes, and
`fit_gaussian_splats` returns exactly one — so the five shipped archives with no
ladder were precisely the joint-fitted ones. None of the twenty-one carried a
substitutive level at all.

`luxar.demos._lod_policy` makes the choice explicit and shares the per-recipe
parameters, so two demos asking for the same topology cannot drift apart. Six
demos now route their cache write through it: `cryoem_virus`,
`ct_totalsegmentator`, `milky_way_dust` and `visible_human_head` take coarse→fine
`levels`, being large single objects that get orbited; `cmu1_pathology` takes
`adaptive` spatial tiles, being a 33000×46000 slide that gets panned and zoomed;
`nexrad_supercell` takes a plain `stream` ladder, its per-frame archives being
small enough to load whole.

Choosing `adaptive` changes how a demo READS its own cache, which is the part
that does not announce itself: a `kind=partition` store has no flat matrix form,
so `GSplatData.load` — and `load_dataset_gsplats`, which ends in that same call —
refuses it. cmu1 now fetches paths and grafts each channel with
`add_gsplats_from_file`. Two incidental things go with it. The scene keeps slide
pixel coordinates instead of re-centring on a shared centroid (the three channels
are fits of the same image on the same grid, so they were never out of alignment,
and the viewer frames on the bounding-box centre either way), and the old
per-channel `scale_intensity(0.1)` is dropped as the no-op it was — a colormapped
gsplat layer is windowed by its own `amplitude_data_range`, so a global amplitude
scale cancels. `load_dataset_gsplats` now says all of this when handed a
partition, instead of surfacing a bare "node is not matrix-shaped".

Substitutive levels cost bytes, and the honest figure is worth stating: on
ct_atlas (660,934 splats) `levels` takes 9,635 KB where `stream` takes 6,966 KB,
so +38%. The same comparison on a 743-splat fit reads 3.6×, which is
per-zarr-group overhead rather than data — a difference recorded next to the
policy, since the misleading number is the easier one to measure.
