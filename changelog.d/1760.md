#### The shared E2E fixture stops paying for a second opinion on a verdict it already reached

The console-error teardown in `src/tests/e2e/fixtures.ts` ran two gates. The
first is Playwright's own: `page.on('console')` filtered to `msg.type() ===
'error'`, plus `page.on('pageerror')`, matched against
`DEFAULT_ALLOWED_CONSOLE_ERRORS`. The second was `assertNoConsoleErrors(page,
DEFAULT_ALLOWED_CONSOLE_ERRORS)`, which reads the viewer's own in-page
interceptor buffer through a `page.evaluate`. The second one is gone.

It was never a second signal for the question being asked.
`assertNoConsoleErrors` consults `messages.errors` and nothing else — never
`warnings`, `logs` or `all` — so in the fixture it re-decided exactly the verdict
the line above had just rendered, from a strictly narrower source. Every write
into that in-page buffer goes through the interceptor's private
`captureMessage`, which is reachable only from the five `patch()` closures in
`src/utils/console-interceptor.ts`, and each of those unconditionally re-emits
through `this.originalConsole.<method>(...)`: whatever lands in the buffer also
crosses Playwright's console channel. The buffer is narrower on five further
axes — it captures only from `patch()` onward, so a pre-init `ReferenceError` or
a mistyped asset is invisible to it; it is a ring that evicts at
`DEFAULT_MAX_BUFFER_SIZE` where the fixture's array is unbounded; it resets on
navigation; it never sees `pageerror` or browser-generated errors the app did
not route through `console`; and it never sees a web worker's console messages,
which Playwright forwards to the page's `console` event but which the in-page
interceptor — patching the main-thread `console` only — cannot reach.
`console.assert` and `console.trace` are a wash rather than a sixth axis: the
interceptor patches neither, and they arrive over CDP as console message types
`assert` / `trace`, which the fixture's `msg.type() === 'error'` filter drops,
so neither source sees them.

What it did cost was time, on exactly the runs that could least afford it. The
`page.evaluate` round trip is the one part of the teardown a saturated main
thread can withhold: #1651 measured a trivial evaluate unanswered for 5 s twelve
times running, and #1760 reproduced 95 s without a single serviced round trip on
a 2-CPU browser while nineteen console messages arrived through
`page.on('console')` in the same window. Since #1651 that stall is bounded at
45 s rather than eating the whole test budget — the fixture call site that
entry describes is the one deleted here — but 45 s is still 45 s, charged to
each of the 59 of 67 specs that import `test` from `./fixtures`, on precisely the
loaded machine where the whole-suite wall clock is what the E2E daemon kills the
run on. An earlier attempt at this kept the probe and forgave its starvation with
a `testInfo` annotation; that annotation has no consumer (`playwright.config.ts`
reports `html` + `list`, and the daemon's `--reporter=json` parser reads status
and error message only), and it still paid the 45 s. Deleting the call is the
smaller and strictly better change: `getConsoleMessages` keeps its plain `Error`,
and the error class, type guard and description helper that attempt introduced
are not needed.

Specs are unaffected, because the in-page buffer was never only the fixture's.
`assertNoConsoleErrors`, `assertConsoleContains`, `assertConsoleDoesNotContain`
and `assertNoShaderErrors` all read it, the last two over `all` and over
`errors` + `warnings` respectively — buckets with no Playwright-side gate at all
— and `hover-tooltip`, `hover-overlay`, `mouse-interactions` and
`recording-panel` deliberately call `assertNoConsoleErrors(page)` with NO
allow-list from their own `test.afterEach`. That extra strictness is the point of
those calls and is left exactly as it was.

One pre-existing ordering bug is fixed while the teardown is open: `page.off`
for both listeners used to run before the gate filtered what they had captured,
so anything emitted after the gate began could not be seen. They now come off in
a `finally` that runs after the verdict, which also detaches them on the two
early-return paths (the `allow-console-errors` annotation, and a test that
already failed or timed out). With the `assertNoConsoleErrors` await removed the
window this closes is zero-width today — nothing between `use(page)` returning
and the filter yields to the event loop — so this is an invariant made true by
construction rather than an observable fix, and it is what keeps the deletion
safe if an `await` is ever reintroduced there.

The gate's decision is now the exported pure function
`unexpectedConsoleErrors(captured, allowed)` instead of a `filter` buried in the
teardown closure, so it is testable without a browser:
`src/tests/unit/tests/e2e-fixture-console-gate.test.ts` pins that an allowed
pattern drops its entry and an unmatched one survives, that the allow-list is
applied per entry rather than to the joined report string (a gate matching
against the join would let one forgiven 404 pardon a real `TypeError` beside
it), that a `pageerror` is judged exactly like a `console.error`, that every
pattern is tried and capture order is preserved among survivors, that the
function reads no environment of its own, and that an empty capture yields
nothing without throwing. Each of those was checked by mutating the production
line and confirming the corresponding assertion goes red.
