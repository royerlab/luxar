#### Read a zipped scene (`.zarr.zip`) in the viewer, uncached

A `.luxar.zarr.zip` can now be opened directly with `?src=`, without unpacking it
first: each chunk is one member of the archive, so the viewer reads it in place over
HTTP range requests. Startup routing recognises an archive instead of HEAD-probing for
child documents that an archive can never have (all three probes 404, which previously
diverted a perfectly loadable dataset into the dataset browser), and the scene-identity
watchdog skips zipped stores, whose root attrs live inside the archive and so would have
raised a permanent false "scene changed" banner.

This is deliberately narrow for now — a zipped store bypasses the L1/L2 chunk cache,
because no zip byte source is wired into the chunk cache yet. It reads
uncached rather than 404ing every chunk, and directory stores are
unaffected. Image overlays are likewise unsupported on a
zipped store (they are fetched by URL, and an archive member has none); they are skipped
with a warning rather than firing a malformed request.

Two failure modes that would otherwise be silent are now loud. A server that ignores
`Range` answers `200` with the whole file; the upstream reader accepts that as if it were
the requested slice, so the zip parser reads the wrong bytes at every offset and a
perfectly good archive looks corrupt. Every ranged read now requires `206`, and a missing
or forbidden archive is reported as such instead of being blamed on Range support.
Likewise an archive built with `zip -r` wraps the store in a directory, and since entry
lookup is verbatim that would miss on every key and render an empty scene; a single
wrapping directory is now detected and stripped, and an archive holding no store — or two
— is refused by name rather than guessed at.

`luxar serve` now exposes `Content-Range`, `Accept-Ranges` and `Content-Length`
through CORS. Only a short header safelist is readable cross-origin by default, and the
viewer runs on a different port from the data server in the documented setup, so without
this a zipped store could not see the range metadata it validates against.
