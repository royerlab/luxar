#### A pre-publish gate for the Zenodo records

`scripts/zenodo_migration_audit.py` grows a `--live` mode: read-only (its only
verb is GET, and a test asserts the source contains no mutating verb and no
publish call) and run immediately before a human publishes the drafts. It checks
every hosted file against its pin **in both directions**, that no scratch or
probe object was left behind, that the contents table matches the file count, and
that the size claims in the prose agree with the files.

Each check exists because that mistake was made. The size audit alone found
**20 of 23** size claims in the record descriptions stale — they predated the
refit and rebuild campaign — including one that described a build that was
evaluated and rejected, down to its tile count and per-level splat totals.

It lands in the existing audit rather than as a fourth Zenodo script, because
"is this ready?" is the question that audit already owns, and because the audit
already resolves the `files` vs `variants.*.files` duality that any pin walk
needs. The default stays entirely local and offline.

The one check that is not a size comparison: when nearly every pin disagrees with
the records, it says so as a diagnosis — *this is probably not the manifest that
will ship* — rather than reporting the mismatches as that many broken files. That
came out of a real incident where an audit run against a superseded manifest
reported the records stale everywhere and was believed; the records were ahead,
and the re-pin was sitting in an unmerged branch. Correct-looking output about the
wrong input is otherwise indistinguishable from a real defect.
