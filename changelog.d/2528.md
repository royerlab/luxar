#### Viewer load and render performance

The viewer now measures how many elements each data node projects per drawing-buffer pixel and acts on it: additive, luminous and volumetric nodes that are denser than a few elements per pixel are thinned on the GPU with a hashed keep-fraction ladder and brightness compensation (a **Density Guard** toggle in the Performance popover turns it off per scene, with a live readout of how many nodes are thinned and how far; `?noDensityGuard` does the same for one session; the data monitor's scene graph marks each thinned node with a lattice-glyph `1/K` chip beside its LOD chip, since thinning changes what is drawn, not what is resident; the draw-order chip likewise trades the word `transparent`/`opaque` for a bucket glyph, with the full explanation in both tooltips), and the refinement loop defers additive rungs a node cannot show until the camera moves in. On the 1.5 M-point dense example this takes a framed view from 43 ms to the display's 8 ms frame budget at the same mean luminance; the 14.8 M-splat pathology slide drops from 114 ms to 67 ms per frame.

Startup no longer runs the load pass twice: the post-load slice update is skipped when the view state is unchanged, which removes the second query/decode/commit of every node (main-thread long tasks −65 to −70 % on the audited scenes) and lets the first refinement run finish instead of being cancelled. Large 3-D gsplat nodes project in a worker, the OPFS write queue accepts a much deeper burst of small chunks while bounding retained pending bytes to the larger of the L1 cache budget and 64MB, points and lines loaders skip the 404 probes for optional arrays the store listing rules out, blend-mode warm-up shares one compiled keeper per program variant across nodes (400 → 4 idle callbacks on the 100-node benchmark), and the adaptive-DPR controller stops learning from frames while the viewer is still loading or refining.

Observability landed first: `__luxarDebug.getPerf()` exposes a load timeline (`loadStart` → first commit → `sceneLoaded` → `refinementComplete`), renderer counters, adaptive-DPR diagnostics, projected density per node, cache and warm-up stats, and an `isSettled` flag probes can wait on; `pnpm test:perf:e2e -g "viewer audit"` reproduces the audit's measurements against the production bundle and `scripts/perf-diff.mjs` diffs two runs. `luxar info --stats` warns when a store's mean chunk is small enough to be round-trip bound on an HTTP/1.1 host such as `luxar serve` (10.6 s vs 4.0 s over HTTP/2 for the same 1.5 M points at 25 Mbps / 30 ms).

A pre-existing picking bug surfaced by the change was fixed on the way: pick materials of nodes registered after the scene load never bound their element texture, so first-load hovers on points and lines resolved nothing.
