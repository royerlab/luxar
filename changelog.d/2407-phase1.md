#### Depth-shard meshes for order-dependent nodes

Machinery for splitting one order-dependent node's draw into several contiguous
depth ranges, so ranges belonging to *different* overlapping nodes can eventually
be interleaved instead of one node drawing entirely before the other
(`docs/guides/specs/CROSS_NODE_DEPTH_ORDERING_SPEC.md`).

Inert: no node is split yet, so every scene draws exactly as it did, and the rest
of the viewer's test suite passing unchanged is the evidence.

The shape is worth recording because two obvious-looking alternatives are wrong.
A node's own mesh draws the first range rather than being left drawing nothing —
several parts of the viewer treat "a mesh that has a material" as the whole node,
or bail on a zero instance count, so an empty parent would have silently broken
level-of-detail cross-fading, camera framing, shader warmup and scene statistics.
And the extra meshes hold *views* into the one ordering array the node already
has rather than copies of it, so every existing writer of that array keeps
working untouched and no ordering bytes are duplicated.

Two surfaces get explicit handling because both would have failed silently.
Picking widens a split node back to its whole population for its own pass (which
is order-independent, so it wants one draw) and restores it afterwards —
otherwise hover would simply stop working over most of the node. And disposal
skips the extra meshes, whose geometry shares every buffer with the node's own:
disposing one would free the node's buffers out from under it.
