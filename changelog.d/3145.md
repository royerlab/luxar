#### Render gate: WebGPU throughput, wider --backends, and A/A runs that pass

The perf suite syncs the GPU after every orbit frame, and on WebGPU that sync
is a round trip of up to ~4 ms through the GPU process. Results that land
during the wait, such as a finished depth sort, add renders to the same frame,
so WebGPU `frameMs` and `rendersPerFrame` read high: on obsidian,
`perf-splats-1m-normal` showed 20.6 ms per synced frame against 10.2 ms
pipelined, and `perf-partition-normal` 1.35 renders per frame against 1.01.
Each arm now also runs the orbit without the per-frame sync and syncs once at
the end. The result is reported as `throughputMs`, judged like the other
timings, and the bias is described in the guide. On WebGL a pipelined frame
is still paced at 60 Hz, so `throughputMs` there only resolves scenes heavier
than that.

`--backends` now replaces a suite's default backend list rather than only
narrowing it, so the `hosted`, `trees` and `cache` suites, which default to
WebGL for a short run, can run on WebGPU without a derived manifest. A case
that names its own backends, like `webgpu_idle_uploads`, keeps them.

The A/A floor is a 95% band for one comparison, but a full perf run makes 208
of them, so identical builds failed most runs on noise alone. The floor the
verdict uses is now widened for the number of judgements in the run
(Bonferroni). Re-partitioning an obsidian A/A run into 100 pseudo-runs, the
share with a false fail fell from 39% to 6%. `gpuMs` keeps the minimum of its
five repetitions, which spread less between arms than their median did on the
same data. Every arm now records the host's load average, and the report warns
when the host was busy. `report.json` also keeps each row's raw samples.

Gating timing metrics in each manifest suite use the same family-wise correction,
counted across the suite's selected cases and backends; report-only timings
and counters do not enter that count. The original one-comparison band remains
available as `aaFloor` alongside the verdict's corrected `floor`.

A suite case whose store is missing now names the command that writes it.
`make render-gate` runs the scene generator with the new `--missing` flag, so a
store added after `datasets/gate` was first generated is written on the next
run. Before, the generator only ran if one particular store was absent.
