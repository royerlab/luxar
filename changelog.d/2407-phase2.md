#### Cross-node draw order can now interleave two overlapping nodes

Draw-order assignment for order-dependent geometry becomes a merge over depth
ranges rather than a strict one-node-after-another emission, so two spatially
overlapping nodes can composite correctly against each other instead of one
drawing entirely before the other.

Still inert — no node is split into ranges yet — and with nothing split the
assignment reduces to the previous behaviour integer for integer, which the
existing draw-order tests passing unchanged is the evidence for.

The merge consumes each group of meshes as a stream that is only ever read
front-to-back, which is what preserves the exact painter order inside a spatial
partition: that order is never re-derived from a comparison, so an imprecise or
slightly stale depth key can choose the wrong stream next but can never
mis-order one node's own ranges. A node that is not split is still emitted as a
whole — a whole-node centre is not a depth interval, so interleaving by it would
change draw order without improving accuracy.

The existing rule that a large node containing a small embedded one must draw
first is preserved: the contained node's stream stays blocked until the
container's is exhausted.
