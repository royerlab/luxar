#### Two dataset-browser E2E guards were waiting on the wrong readiness signal

The `first-time-ux` specs that exercise the `O` shortcut gated on
`window.__luxarDebug.app`, which the bootstrap publishes at construction — before
`LuxarApp.init()` has finished. The window-level `open-dataset-browser` listener is
installed only at the _end_ of `init()`, after the awaited dataset load, so the `O`
keypress dispatched its event into the void and both tests died on their first
assertion.

What that cost is worth recording: the Escape exemption in `InputHandler.onKeyDown`
— the one that lets Escape reach the context manager even while focus sits in a text
input — had no working regression guard, and neither did the `O` toggle's
reopen-after-Escape path, which depends on `DatasetBrowser.close()` firing `onClose`
so the next press does not toggle a phantom browser shut. Both are guarded again.

The tests now gate on `waitForLuxarReady`, focus the canvas through the shared
`focusCanvas` helper instead of a bare click whose failure was swallowed, and assert
explicitly that a `?src=` load does not auto-open the browser — an assertion that has
to come before the focus click, which would Escape the browser away and make it
vacuous.
