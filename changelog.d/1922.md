#### `H` and `O` are toggles again: panels no longer autofocus their filter field

`InputHandler.onKeyDown` drops every key except `Escape` while focus is on a
typing surface, which is what lets a user type into a search box without
flipping dimensions or cycling camera modes. Two panels then autofocused a text
filter as they opened — the help overlay handed focus to its filter on a 0 ms
timer, and the dataset browser had a one-shot "first successful listing claims
focus" block — so each panel's own toggle key became one-way: `H` opened the
help overlay, but the second `H` was swallowed as typing and the overlay never
closed. Nothing was trapped (Escape, the close button and clicking away all
worked, and the rail button closed it because a pointer click blurs the filter
first), but the docs, the binding description and the rail tooltip all promised
a toggle.

Both panels now park initial focus on the panel **container** instead. A
`<div role="dialog">` is not a typing surface, so the guard never engages and
the toggle key reaches its global binding. Type-to-filter is preserved by a new
shared helper, `ui/help-overlay/type-to-filter.ts`: a container-level `keydown`
listener forwards the first printable keystroke into the filter — focusing it,
appending the character and dispatching the `input` event the panel's existing
filter handler already listens for — so filtering still starts on the very first
key the user presses, whenever a filter is on screen at all (the dataset browser
hides its search bar while loading, on an error and in an empty directory; keys
pressed in those states are contained by the modal, since there is nothing to
narrow and nothing behind the panel should hear them). `Tab` still reaches the
focus trap,
`ArrowDown` still moves into the dataset listing (from the container now, since
the search field no longer has focus to hand off), a keystroke that opens an IME
composition focuses the filter without preventing the composition — so CJK and
European dead-key layouts keep their first character — and an AltGr-composed
printable (`AltGr+2` = `@`, which Windows reports as ctrl+alt) types like any
other character rather than being mistaken for a shortcut. `Space` is not a
filter character: a leading space matches nothing and it scrolls a
`tabindex="-1"` container. The dataset browser's manual-entry fallback — the
form shown for a server that cannot be listed at all (S3/CloudFront, nginx with
`autoindex off`) — no longer autofocuses its path field either, but it is
deliberately *not* wired into type-to-filter: that field takes a URL, not a
filter query, so stray keystrokes should not be routed into it. Focus stays on
the container and the user clicks or tabs into the field, which is a deliberate
act; from there the ordinary typing guard applies exactly as it does for every
other text field in the app, `Enter` still submits and `Escape` still closes the
panel.

Dropping the autofocus removed something nobody had noticed it was doing: the
focused text field was the only thing keeping global shortcuts out of the scene
behind an `aria-modal` panel, because no panel pushes an `InputContext`. So the
container listener now contains them itself, and the rule is unconditional on
focus: every key that bubbles up to the panel container is `stopPropagation`ed
— from the shell, from a listing row, from the filter, from a breadcrumb alike
— so `Home`/`End` no longer jump the selected dimension and `Shift`+arrows no
longer change the animation speed while a panel is open, not even after a
single `Tab`. A key an inner handler already consumed (`preventDefault` without
`stopPropagation`, which is how the listing's arrow navigation is written) is
contained too rather than released to the globals; the inner handlers
themselves are unaffected, since they run first on the way up.

There are exactly three exceptions. `Escape` (panel dismissal), `Tab`/`Shift+Tab`
(the focus trap), and the keys the panel *advertises* — which is now more than
its own toggle: containment silences everything else, so a shortcut a panel
offers as a **live affordance** must be declared or it is dead. The dataset
browser's welcome banner shows an `H` Help chip you are meant to press right
there, so it declares both `O` and `H`; the help overlay declares `H`. The rule
is about affordances, not about every `<kbd>` on screen: the help overlay's
reference table lists `O`, `V`, `F`, `R`, `B`, `1`–`9` and the rest as a
*catalogue* of what those keys do when the panel is closed, and they are
correctly inert while it is open — as they already were before this change,
when the autofocused filter fed them to the typing guard.

That exemption is gated on the event target being the container itself, so once
focus has moved into a field or a row those keys are ordinary characters again
and typing `o` into the path field cannot close the browser.
Containment is `stopPropagation` only, never `preventDefault`, so panel
scrolling with `Home`/`PageDown` and every browser-level shortcut (`Ctrl+F`,
`Cmd+W`, `F5`, the function keys) keep working.

One character genuinely cannot serve both masters. Forwarding the first `h`
into the help overlay's filter would re-break exactly the toggle this change
fixes, so a panel's own toggle key is passed through to the global binding and
cannot be the *first* character of a filter query. It types normally once the
filter has focus, `Shift`+that key types it even as the first character (the
global lookup spells the shifted form `"h+shift"`, which no binding registers,
so passing it through would only make it a dead key), and matching is
case-insensitive — so no query is unreachable, and "help" is also found by
typing `elp`.

While the wording was under review anyway: `O` has toggled the dataset browser
since the shortcut was wired through `installBrowserShortcut`, but the binding
description, the help overlay row, the viewer guide and the viewer README all
still said "Open dataset browser". Now that the keyboard round-trip actually
works, they say "Toggle".

`trapFocus` gained an `autoFocusFirst` option because the two mechanisms would
otherwise fight: the trap parks initial focus on the container's first focusable
element via its own 0 ms timer, which would fire after the panel's synchronous
container focus and silently win. The filtered panels pass `false`; the error
overlay is unchanged. The trap also learned to steer `Tab`/`Shift+Tab` inward
when focus is on the container itself — otherwise the browser default would walk
Shift+Tab straight out of a modal whose focus now starts on a `tabindex="-1"`
element — and to skip focusables that are not rendered, since the dataset
browser hides its whole search row while a directory loads and `Shift+Tab` would
otherwise aim at a `display: none` input, which a real browser refuses to focus.

Finally, the trap's cleanup now restores focus to the element it recorded on
entry only when focus is still *inside* the container it is releasing. Modals
stack: open the help overlay from the rail, then open the dataset browser on top
of it, then press `H` (which the browser declares as a passthrough) — that
closes the help overlay, and an unconditional restore sent focus back to the
rail button, i.e. straight out of the still-open browser dialog, where the
global shortcuts start reaching the scene again. That is precisely the invariant
this change exists to establish, so the restore is now conditional.

Dataset-browser rerenders preserve the same invariant: when a navigation
loading state, breadcrumb rebuild or cancelled path edit removes the focused
child, focus returns to the panel only if it fell back to `null` or `<body>`.
That narrow check keeps modal containment active without taking focus from a
dialog stacked on top.
