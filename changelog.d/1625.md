#### `inspect_gsplats_zarr()` now works on a compressed archive, and stops inventing a compression ratio (#1625)

`save_gsplats(..., compress="zip")` nests the store one directory deep inside
the archive (`a.gsplats.zarr/.zgroup`, …), but the inspector handed the archive
path straight to `open_group`, so inspecting an archive Luxar wrote itself died
with `GroupNotFoundError`. It now resolves the store root through the same
helper `load_gsplat_node` uses — extract to a temp directory, open the resolved
store, remove the temp directory in a `finally` — and gives the same clear
`ValueError` as the loader for a regular file that is not a `.zip`/`.tar.gz`.

The other archive shape is the *flat* one, whose store sits at the archive root
(`zip -r x.gsplats.zarr.zip .` from inside a store, or a zarr-native `ZipStore`
write). Zarr opens that shape in place, so the inspector always could read one —
and did, which is where the size bug below was measured. Sharing the resolver
must not quietly break that, so the resolver recognises the flat shape from the
zip index (a group document at depth 0 and nothing under a top-level
`*.gsplats.zarr/` directory) and hands the archive itself to `open_group`
instead of extracting it. That path is opt-in (`flat_zip_in_place=True`) and
only the inspector opts in: `load_gsplat_node` never accepted a flat zip and
still does not, because the appearance peek and the `gsplat info` CLI resolution
do not handle that shape either. A `.tar.gz` is still always extracted; zarr has
no tar store, so a flat one was never openable.

The size was wrong too. The storage walk only summed a directory's files and
scored anything else as `0`, so a single-file archive reported `storage_bytes:
0` and the compression ratio then fell onto its `total_bytes > 0 else 1.0`
guard — `format_gsplats_info()` printed "0.0 MB, 1.0x" for a real dataset. A
non-directory path is now sized by its own `st_size`, measured on the path the
caller supplied (the archive's bytes, not the extracted copy, which is what
"how big is this on disk" means). When the size genuinely cannot be measured,
`compression_ratio` is `None` rather than a fabricated `1.0`, and the formatter
prints the size line without a compression figure.
