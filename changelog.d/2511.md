#### The encoding vocabulary can no longer be misspelled

Luxar's on-disk encoding names carry two bit-width suffix conventions — the
per-channel family writes `_uN`, the scalar / bounded / lut / rgb families write
`_uintN` — and six documents used the wrong sibling of a real name, including
the published gsplats format spec and a docstring forty lines above the code
that emits a different name. All six are corrected.

The conventions themselves stay. Both spellings are live in published stores, so
renaming either would invalidate every published store and checksum-pinned
record; `format-contract/contract.yaml` now records that measurement and the
reasoning, rather than leaving the split looking like an oversight.

Two gates enforce it instead. One asserts that no document names an encoding
absent from the contract, deriving the wrong-convention siblings from the
contract itself so a new encoding is covered as soon as it is added. It reads
prose deliberately: a misspelling reaches a docstring before it reaches an
f-string. The other closes the reverse direction of the existing emitted-names
check — every quantized name in the contract must be reachable by some producer,
or recorded as unreachable with its reason. Existing producer tests covered
individual names, but nothing enforced that reverse subset across the complete
contract, so a dead entry or a whole family disappearing from the producer
surface could go unnoticed.
